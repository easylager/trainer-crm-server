# Концепция UX: Выбор тренера + Запись + Заявки

## Когда «общая» и когда «персональная» заявка

- **Персональная заявка** — «хочу заниматься у этого тренера, но слотов нет / хочу обсудить». Логичное место: **только на карточке тренера** (после того как пользователь его открыл). Дублировать на главной странице выбора не нужно: пользователь ещё никого не выбрал, персональная заявка «для кого-то» с главной создаёт путаницу.
- **Общая заявка** — «по этому городу/услуге тренера нет или ни один не подошёл, подберите мне вариант». Логичные места:
  1. **Пустой список тренеров**: «Тренеров по вашему запросу пока нет. Оставьте заявку — подберём вариант.» Один явный CTA.
  2. **Внизу списка тренеров** (когда список не пустой): «Не нашли подходящего? Оставить заявку» — для тех, кто просмотрел карточки и решил не записываться, но хочет, чтобы с ним связались.

**Главная страница («Ваш выбор»)** не должна предлагать ни «Оставить заявку для тренера», ни «Общую заявку»: там пользователь только настраивает фильтр (город, услуга, арена) и переходит к списку. Заявки появляются **в контексте** — после просмотра списка или карточки.

## Клиентские сценарии (как в сильных системах)

- **Сценарий A — «Знаю, что хочу»**  
  Город/услуга → список тренеров → карточка → слоты есть → запись. Или слотов нет → «Оставить заявку» (персональная) на карточке.

- **Сценарий B — «Никого нет по запросу»**  
  Город/услуга → список пустой → экран «Тренеров пока нет» + одна кнопка «Оставить заявку — подберём вариант» (общая заявка).

- **Сценарий C — «Посмотрел, не подошло»**  
  Список есть, пользователь листает, но не открывает запись → внизу списка: «Не нашли подходящего? Оставить заявку» (общая заявка).

- **Сценарий D — «Хочу обсудить с конкретным тренером»**  
  Открыл карточку → нет слотов или не хочет сразу в слот → «Оставить заявку» на карточке (персональная).

- **Сценарий E — «Список есть, но ни у кого нет свободных слотов»**  
  Город/услуга → список тренеров не пустой → пользователь открывает карточки, везде видит «Сейчас нет свободных слотов». Важно: на каждой карточке явно показать, что делать дальше — **«Оставить заявку»** (персональная): тренер получит заявку и предложит время. Подпись рядом с блоком слотов помогает: «Оставьте заявку — тренер предложит удобное время». Альтернатива: пользователь не хочет выбирать «кого-то одного» и уходит в список → внизу списка «Не нашли подходящего? Оставить заявку» (общая заявка). Оба пути валидны.

Итог: на главной только фильтр и один призыв — «Показать тренеров». Заявки — только там, где им есть смысл (пустой список, низ списка, карточка тренера).

## Другие сценарии и краевые случаи

- **Ошибка загрузки слотов** (сеть, таймаут): на карточке показываем «Не удалось загрузить слоты», кнопку «Оставить заявку» оставляем — пользователь может оставить заявку без выбора слота.
- **Выбрал город, но не услугу** (или наоборот): кнопка «Показать тренеров» недоступна или ведёт к пустому списку — в текущей логике требуются город + услуга. Это ок: фильтр ведёт к осмысленному списку.
- **Список пустой из-за арены**: пользователь выбрал узкую арену → 0 тренеров → пустой список + «Оставить заявку». Сценарий уже покрыт.
- **Сохранил тренера в меню, потом передумал**: можно снова зайти в каталог, выбрать другого и записаться/оставить заявку; «выбранный» в меню просто даёт быстрый вход в расписание.
- **Оставил общую заявку, потом нашёл тренера**: может спокойно записаться с карточки; общая заявка и запись не конфликтуют.
- **Хочет обсудить перед записью** (есть слоты, но не нажимает «Записаться»): на карточке есть «Оставить заявку» — тренер увидит заявку и сможет написать/предложить время.

## Проблема (исходная)

- В каталоге нельзя ни записаться к тренеру, ни увидеть свободные слоты.
- Чтобы записаться: выбрать тренера → выйти в меню → «Записаться к выбранному тренеру» → только тогда расписание. Если слотов нет — возврат в каталог и по кругу.
- Заявку можно оставить, но путь «запись vs заявка» размазан по разным местам, много шагов и догадок.

## Референсы (похожие системы)

- **Calendly / Cal.com**: выбор типа встречи → сразу календарь/слоты → бронь. Нет «сначала выбери, потом иди в другое место за временем».
- **Fitness/wellness (Mindbody, ClassPass)**: тренер/класс → видно «есть слоты» или даты → запись в 1–2 шага.
- **Запись к врачу (Zocdoc и др.)**: врач → «ближайшая дата» или список слотов на карточке → запись без ухода в главное меню.
- **Airbnb**: поиск → карточки с ключевой инфой (цена, даты) → клик = детали + бронирование в одном потоке.

Общий принцип: **контекст не теряется**. Пользователь остаётся в одном потоке: нашёл тренера → сразу видит возможность записи и слоты (или их отсутствие) → либо записывается, либо оставляет заявку.

## Целевой UX (единый поток в каталоге)

### 1. Карточка тренера = точка принятия решения

На экране тренера пользователь видит всё нужное и делает один выбор:

- **Блок «Ближайшие слоты»**  
  - Загружаем слоты (текущая неделя + следующая) через существующий API.  
  - Показываем 5–8 ближайших слотов (дата + время).  
  - Если слотов нет: текст «Сейчас нет свободных слотов».

- **Две явные действия**  
  - **Записаться** — показываем только если есть слоты. Ведёт к выбору слота и форме (телефон, комментарий) **в том же Mini App**.  
  - **Оставить заявку** — всегда доступно. Ведёт к форме заявки (персональная для этого тренера), как сейчас.

- **Опционально**  
  - Ссылка «Сохранить как выбранного в меню бота» для тех, кто привык к кнопке в главном меню (можно убрать позже).

Итог: не нужно «выбрать → выйти → записаться к выбранному»; слоты и запись — прямо из каталога.

### 2. Запись без выхода из каталога

- Нажатие **«Записаться»** на карточке тренера открывает экран выбора времени (те же слоты, что уже загружены, или доп. неделя при необходимости).
- Выбор слота → форма: телефон, комментарий (как в текущем экране записи).
- Отправка → экран успеха «Вы записаны. Ожидайте подтверждения» и кнопка «Закрыть».

Всё в одном Mini App, без перехода в другое место и без лишних шагов.

### 3. Заявка как запасной путь

- Если слотов нет — блок «Нет свободных слотов» + акцент на кнопке **«Оставить заявку»**.
- Если слоты есть — «Оставить заявку» остаётся второй кнопкой (например, «хочу обсудить перед записью»).

Так пользователь всегда понимает: либо запись по слотам, либо заявка, и оба пути стартуют с карточки тренера.

### 4. Сводка преимуществ

- Меньше шагов: выбор тренера и запись/заявка в одном потоке.
- Нет «слепого» выбора: слоты видны до решения записаться.
- Нет круга «выбрал → нет слотов → назад в каталог»: слоты и «нет слотов» видны на карточке.
- Один экран принятия решения: карточка тренера с слотами + «Записаться» / «Оставить заявку».

## Реализация (кратко)

- **Каталог (trainer detail)**  
  - При открытии карточки: `GET /api/webapp/client/slots?trainer_id=X`.  
  - Блок «Ближайшие слоты» (список дата+время) или «Нет свободных слотов».  
  - Кнопки: «Записаться» (если есть слоты), «Оставить заявку».

- **Новые экраны в том же Mini App**  
  - Выбор слота (компактный список).  
  - Форма записи (телефон, комментарий) → `POST /api/webapp/client/booking`.  
  - Экран успеха записи.

- **Главное меню бота**  
  - Кнопка «Записаться к выбранному тренеру» остаётся для быстрого входа тем, кто уже выбрал тренера ранее (открывает текущий book Mini App с `trainer_id`).

После внедрения каталог становится единственным местом, где пользователь выбирает тренера и сразу решает: записаться по слотам или оставить заявку.
