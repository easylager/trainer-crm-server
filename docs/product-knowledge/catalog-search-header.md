# Шапка вкладки «Поиск» (каталог)

**Date:** 2026-10-03  
**Макет:** [`design/prototypes/2026-10-03-catalog-header-chrome.html`](../../design/prototypes/2026-10-03-catalog-header-chrome.html) (вариант **A′**)

## Пустой выбор — не «всё подряд»

- **Верхний сегмент** всегда занят одним **родом**: **Места** · **Тренеры** · **Магазины**. Сегменты с нулём в городе не рисуются.
- **Пустой фильтр типа** внутри **Места** = одна **смешанная лента площадок** (лёд, зал, улица, при данных — хореография, бассейн). Запрос без `venue_type`.
- **Тренеры** и **магазины** в эту ленту **не входят** — только отдельный сегмент. Смешанная лента «катки + тренеры + магазины» без секций не делается.

## Второй уровень (только «Места»)

- **Лёд / Зал / Улица** — тихий underline-ряд «Все · …», если в городе ≥2 живых типа из этой тройки.
- **Хореография, бассейн, другое** — не раздувают шапку: одна кнопка **«Все места ▾»** с полным списком типов и счётчиками (когда в городе есть типы вне тройки или длинный хвост).
- Тип с count=0 не показывается.

## Окно времени

- Только когда в выборе есть **лёд** (все места с льдом в городе или фильтр «Лёд»). У зала, улицы без сеансов, магазина и тренеров — нет.
- В UI — одна кнопка + выпадающий список, не ряд из четырёх чипов.

## «Ближе» у списка

- Сортирует **текущую** ленту по расстоянию от пользователя (параметр `near` в API). Город в шапке не меняется.
- Нужна **геолокация**. Если город уже выбран, а GPS недоступен — показываем объяснение и «Понятно», без кнопки «Выбрать город».
- Выбор города в этом сценарии предлагается только когда города ещё нет.

## Домен

- Открытый **каток с расписанием** — `ice`. **Лыжероллер** и прочая площадка без сеансов — `outdoor`. См. [`src/shared/venue_types.py`](../../src/shared/venue_types.py).
