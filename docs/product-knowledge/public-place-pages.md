# Публичные страницы мест и шеринг каталога

Каталог (катки, залы, магазины, тренеры) работает без Telegram-авторизации и без
зарегистрированных тренеров. Его вирусная единица — **публичная страница места**:
её пересылают, по ней приходят из поиска, из неё входят в мини-апп.

## Почему страница, а не ссылка на бота

Ссылка `t.me/<bot>?start=…` даёт превью «бот Glide» (Telegram рисует его по профилю
бота) и не открывается в Viber и WhatsApp. Страница места на нашем домене даёт своё
превью (og-теги + картинка), открывается у любого получателя и индексируется поиском.
Вход в Telegram — кнопка на самой странице.

## Адреса

| Адрес | Что это |
|---|---|
| `/p/{city}/{slug}` | Страница места. `city` — `city_slug(cities.name)`, `slug` — `arena_profiles.slug` (уникален в городе) |
| `?s=<session_id>` | Ссылка на конкретный сеанс: он первым на странице и на картинке. Прошёл — страница честно говорит это и показывает ближайший |
| `?i=1` | Тон «Позвать с собой»: заголовок-вопрос вместо объявления |
| `/p/{city}/{slug}/og.png`, `/story.png` | Превью 1200×630 и сторис 1080×1920 (с адресом на «корешке» — в историях ссылки не кликаются) |
| `/p/{id}` | Короткая форма → 301 на каноническую |
| `/sitemap.xml`, `/robots.txt` | Все опубликованные места и «Лёд сегодня» по городам |

Формы с `?s`/`?i` — `noindex`, canonical — без параметров. Нет места или оно не
опубликовано — дружелюбная 404 с выходом в каталог.

Все адреса собирает `src/application/place_links.py` — не склеивать вручную.

## Что на странице

Общий каркас для всех типов: шапка → статус → действия → контакты → доверие.
Середина своя: у льда — неделя расписания (каждое время — ссылка на `?s=`), у
магазина — услуги, у зала — часы. Пустая секция не рисуется: нет данных — нет
обещания. Ряд «Поделиться» (Telegram, Viber, WhatsApp, VK, копировать) — на самой
странице, чтобы цепочка не обрывалась на первом получателе.

Разметка `schema.org`: `IceRink` / `SportingGoodsStore` / `ExerciseGym` + `Event` на
сеансы с ценой.

Правила текста:

- **Даты на кэшируемых поверхностях — только абсолютные** («Пт, 2 окт»): og:title,
  картинка и текст шеринга живут в кэше Telegram и в чатах днями, «сегодня» там
  становится неправдой. На самой странице (живой) — «Сегодня, Завтра».
- Тёмная подача — только в картинке (экспортируемый артефакт). Страница и мини-апп —
  светлый холст (`design/CREATIVE-DIRECTIONS-2026-08-24.md`).
- Только факты из данных: нет цены — нет цены, не «0» и не «уточняйте».

## Шеринг из мини-аппа

`GET /api/public/arenas/{ref}/share` — тот же контракт, что `/ice/share` и
`share-trainer` (`share_url`, `share_body`, `share_text`), плюс `invite_*`,
`story_image_url`, `og_image_url`. Шит `static/webapp/mini-app-share-sheet.js`:
тон, выбор сеанса, превью той самой картинки, каналы Telegram · Ссылка ·
Картинка · Другое.

Счётчик (`client_share_events`, `kind=place`): превью и переключатели идут с
`record=false`; событие пишется по нажатию канала, канал — в `payload.channel`.
Одна строка — одно намерение отправить, не факт доставки.

## Диплинки

| Параметр | Куда ведёт |
|---|---|
| `arena_<id>` | Карточка места |
| `catalog_<city_id>` | Каталог города |
| `catalog_<city_id>_skate` / `_coach` | Каталог с интентом |
| `catalog_<city_id>_shop` / `_gym` | Каталог с фильтром по типу места |

У клиентского бота настроено основное мини-приложение (BotFather → Main Mini App,
`CLIENT_BOT_MAIN_MINI_APP=true` — по умолчанию): ссылки вида `t.me/<bot>?startapp=…`
открывают мини-апп сразу на нужном экране, без сообщения бота. Если основного
мини-приложения нет (`false`) — `t.me/<bot>?start=…`, и бот отвечает одной кнопкой на
тот же экран (`src/application/catalog_deep_links.py`). Отдельный мини-апп с коротким
именем (`CLIENT_MINI_APP_SHORT_NAME`) — `t.me/<bot>/<app>?startapp=…`. Вкладка «Поиск» читает `?city_id=` и
`?venue=` из ссылки: город из ссылки важнее сохранённого.

## Магазины

`venue_type=shop` — строка в `arenas`, как каток: гео, фото, модерация общие.
Заводит только админ (`/admin/arenas`, `admin-dicts`). Услуги — в
`arena_profiles.amenities`: `retail`, `repair` + общие с катком `skate_rental`,
`skate_sharpening`; набор ключей зависит от типа (`amenity_keys_for_venue`).

- Тренеру магазин как место работы не предлагается (`TRAINER_VENUE_TYPE_KEYS`).
- В ленте «Где заниматься» магазин только по чипу «Магазин», но чип виден всегда,
  когда в городе есть магазины (фасеты считаются до фильтра).
- Поиск находит места по слову услуги («заточка» → `skate_sharpening = true`).

## Маркетинговая ссылка `/go`

`/go`, `/go/<источник>`, `/go/<источник>/<город>` — для постов, сторис, листовок и QR.
Маршрут ограничен публичным лимитом запросов на IP. Настроенные источники пишутся в
`catalog_entry_clicks` (источник, город, куда увели, хост реферера; кто перешёл — не
храним); неизвестный корректный slug всё равно перенаправляется, но не записывается.
Ссылка уводит в Telegram сразу в каталог (`startapp=catalog` /
`catalog_<город>`); без основного мини-приложения — в бота, который отвечает одной
кнопкой «Каталог». Бота нет — веб-каталог. Без города в ссылке каталог один раз
спрашивает геолокацию и берёт ближайший город (не дальше 150 км).

По умолчанию разрешены источники: `insta`, `flyer-olimpik`, `direct`, `other`.
Чтобы добавить кампанию, установите `CATALOG_ENTRY_SOURCE_KEYS` в JSON-массив
slug-ов, сохранив эти четыре ключа, и перезапустите API. Например:
`["insta","flyer-olimpik","direct","other","winter-stories"]`. Slug —
латиница, цифры, `-`, `_`, до 40 символов; список задаётся явно, поэтому случайный
путь не создаёт строку атрибуции. Пустая метка учитывается как `direct`, некорректная —
как `other`.
Смотреть, какой канал работает:

```sql
SELECT source, target, count(*) FROM catalog_entry_clicks
WHERE occurred_at > now() - interval '30 days' GROUP BY 1, 2 ORDER BY 3 DESC;
```

## Подборка `/c/{город}?t=<тип>&w=<окно>`

То, чем делятся прямо из каталога («Поделиться подборкой»): места выбранного типа,
сеансы в окне времени с ценами, ссылки на страницы мест, og/story-картинки, «Открыть в
Telegram» с теми же фильтрами. В sitemap — подборка каждого города и магазины города.

## Окно времени и «Рядом»

Лента принимает `when=auto|today_evening|today|tomorrow|weekend|any`. `auto` — умный
дефолт по дню и часу в Минске (`src/application/ice_time_windows.py`): до 21:00 —
«Сегодня вечером» (и в пятницу), после 21:00 — «Завтра», с пятницы 21:00 до
воскресенья 21:00 — «Выходные». «Выходные» — суббота и воскресенье: пятничный вечер в
окне давал «Сегодня 16:15» под этим чипом. Истории клиента не используем.

Окно **сортирует, а не фильтрует**. Места с сеансом в окне — сверху, обычными
карточками. Остальные — ниже, со своим ближайшим сеансом (`live.outside_window`) и
явно другими: кадр ниже (в цвете), время сжато, на кадре плашка «Завтра нет ·
ближайший», между группами — липкая плашка-разделитель. Карта получает то же окно:
пин вне окна полый и без времени. В окне пусто совсем — подпись ленты говорит об
этом, карточки все в «приглушённом» виде.

Кнопка «Рядом» в строке поиска — переключатель: текущая лента (тип места, окно)
по расстоянию, внутри групп окна. Не «лёд»: в поиске и залы, и заточка. Отказ в
геолокации — попап с «Выбрать город», а не тупик с одной «Close».
`GET /api/public/ice/nearest` остаётся для внешних входов, мини-апп её больше не зовёт.

## Часы работы

`opening_hours` — `{"daily": {"open", "close"}}` или `{"weekly": {"mon": ["10:00",
"19:00"], …, "sun": null}}` (null — выходной). Форма админки знает только «ежедневно» и
не стирает часы по дням, пришедшие из импорта.

## Импорт магазинов партнёра

`data/catalog/shops-<город>.json` + `scripts/load_catalog_shops.py` (dry-run по
умолчанию; `--apply`, `--geocode`, `--i-know-this-is-prod`). Только названные услуги
(не названное — «неизвестно», не «нет»); повторный запуск обновляет; заточка на катке —
только при однозначном совпадении имени, иначе в отчёт.

## Пропущенные катки и локальный каталог «как в проде»

`data/catalog/rinks-<город>.json` — тот же формат и тот же загрузчик, что у магазинов, плюс
`venue_type` (`ice` / `outdoor`), `match` (подстроки имени для поиска уже заведённого места),
`season` (`[11, 3]`) и `tickets_url`. Новый каток создаётся; существующий (из досье или
админки) только **дополняется** пустыми полями — заполненное не перезаписывается, удобства
добавляются к имеющимся.

```
PYTHONPATH=. python scripts/load_catalog_shops.py --file data/catalog/rinks-minsk.json            # план
PYTHONPATH=. python scripts/load_catalog_shops.py --file data/catalog/rinks-minsk.json --apply --geocode --i-know-this-is-prod
```

Локальная база разработчика: `scripts/bootstrap_local_catalog.py --apply --geocode` заводит Минск
и его катки под prod-id (досье, парсеры и фикстуры ключуются по ним), затем запускает досье,
парсеры Минска и областей, магазины, пропущенные катки и разовое чтение расписаний.
Повторный запуск дублей не создаёт. Только локальная база — флага для прода нет.

Юность и СДЮШОР (ledlife) отвечают 403 на небелорусские IP: их парсерам нужен
`BY_EGRESS_PROXY_URL` (прокси/VPS в РБ) у процесса `notification_service`.
