# Публичные страницы мест и шеринг каталога

Каталог (катки, залы, магазины, тренеры) работает без Telegram-авторизации и без
зарегистрированных тренеров. Его вирусная единица — **публичная страница места**:
её пересылают, по ней приходят из поиска, из неё входят в мини-апп.

## Почему страница, а не ссылка на бота

Ссылка `t.me/<bot>?start=…` даёт превью «бот Glide» (Telegram рисует его по профилю
бота) и не открывается в Viber и WhatsApp. Страница места на нашем домене даёт своё
превью (og-теги + картинка), открывается у любого получателя и индексируется поиском.
Вход в Telegram — кнопка на самой странице.

## Адреса

| Адрес | Что это |
|---|---|
| `/p/{city}/{slug}` | Страница места. `city` — `city_slug(cities.name)`, `slug` — `arena_profiles.slug` (уникален в городе) |
| `?s=<session_id>` | Ссылка на конкретный сеанс: он первым на странице и на картинке. Прошёл — страница честно говорит это и показывает ближайший |
| `?i=1` | Тон «Позвать с собой»: заголовок-вопрос вместо объявления |
| `/p/{city}/{slug}/og.png`, `/story.png` | Превью 1200×630 и сторис 1080×1920 (с адресом на «корешке» — в историях ссылки не кликаются) |
| `/p/{id}` | Короткая форма → 301 на каноническую |
| `/sitemap.xml`, `/robots.txt` | Все опубликованные места и «Лёд сегодня» по городам |

Формы с `?s`/`?i` — `noindex`, canonical — без параметров. Нет места или оно не
опубликовано — дружелюбная 404 с выходом в каталог.

Все адреса собирает `src/application/place_links.py` — не склеивать вручную.

## Что на странице

Общий каркас для всех типов: шапка → статус → действия → контакты → доверие.
Середина своя: у льда — неделя расписания (каждое время — ссылка на `?s=`), у
магазина — услуги, у зала — часы. Пустая секция не рисуется: нет данных — нет
обещания. Ряд «Поделиться» (Telegram, Viber, WhatsApp, VK, копировать) — на самой
странице, чтобы цепочка не обрывалась на первом получателе.

Разметка `schema.org`: `IceRink` / `SportingGoodsStore` / `ExerciseGym` + `Event` на
сеансы с ценой.

Правила текста:

- **Даты на кэшируемых поверхностях — только абсолютные** («Пт, 2 окт»): og:title,
  картинка и текст шеринга живут в кэше Telegram и в чатах днями, «сегодня» там
  становится неправдой. На самой странице (живой) — «Сегодня, Завтра».
- Тёмная подача — только в картинке (экспортируемый артефакт). Страница и мини-апп —
  светлый холст (`design/CREATIVE-DIRECTIONS-2026-08-24.md`).
- Только факты из данных: нет цены — нет цены, не «0» и не «уточняйте».

## Шеринг из мини-аппа

`GET /api/public/arenas/{ref}/share` — тот же контракт, что `/ice/share` и
`share-trainer` (`share_url`, `share_body`, `share_text`), плюс `invite_*`,
`story_image_url`, `og_image_url`. Шит `static/webapp/mini-app-share-sheet.js`:
тон, выбор сеанса, превью той самой картинки, каналы Telegram · Ссылка ·
Картинка · Другое.

Счётчик (`client_share_events`, `kind=place`): превью и переключатели идут с
`record=false`; событие пишется по нажатию канала, канал — в `payload.channel`.
Одна строка — одно намерение отправить, не факт доставки.

## Диплинки

| Параметр | Куда ведёт |
|---|---|
| `arena_<id>` | Карточка места |
| `catalog_<city_id>` | Каталог города |
| `catalog_<city_id>_skate` / `_coach` | Каталог с интентом |
| `catalog_<city_id>_shop` / `_gym` | Каталог с фильтром по типу места |

С `CLIENT_MINI_APP_SHORT_NAME` (BotFather → `/newapp`) ссылка —
`t.me/<bot>/<app>?startapp=…`, мини-апп открывается сразу на экране. Без него —
`t.me/<bot>?start=…`, бот отвечает одной кнопкой на тот же экран
(`src/application/catalog_deep_links.py`). Вкладка «Поиск» читает `?city_id=` и
`?venue=` из ссылки: город из ссылки важнее сохранённого.

## Магазины

`venue_type=shop` — строка в `arenas`, как каток: гео, фото, модерация общие.
Заводит только админ (`/admin/arenas`, `admin-dicts`). Услуги — в
`arena_profiles.amenities`: `retail`, `repair` + общие с катком `skate_rental`,
`skate_sharpening`; набор ключей зависит от типа (`amenity_keys_for_venue`).

- Тренеру магазин как место работы не предлагается (`TRAINER_VENUE_TYPE_KEYS`).
- В ленте «Где заниматься» магазин только по чипу «Магазин», но чип виден всегда,
  когда в городе есть магазины (фасеты считаются до фильтра).
- Поиск находит места по слову услуги («заточка» → `skate_sharpening = true`).
