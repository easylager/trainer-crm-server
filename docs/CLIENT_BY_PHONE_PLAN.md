# План: клиент по телефону и запись из расписания

## Идея

- **Уникальный идентификатор** — телефон (нормализованный: только цифры).
- **Тренер в расписании:** выбирает существующего клиента (поиск по телефону / имя+фамилия в реальном времени) **или** добавляет нового (телефон, имя, фамилия) без telegram_id и записывает на слот.
- **Позже:** клиент заходит в бота → вводит телефон, имя, фамилию → получает проверочный код на телефон → после проверки к его профилю привязывается telegram_id.

---

## План по пунктам

### 1. База и модель

- Миграция: `clients.telegram_id` сделать **nullable**.
- Нормализованное поле для поиска: `clients.phone_normalized` (только цифры) + **unique index** по нему (один клиент на номер).
- Ограничение: либо есть `telegram_id`, либо заполнен `phone_normalized` (чтобы не было «пустых» записей).

### 2. Приложение: клиент по телефону

- **get_or_create_client_by_phone(phone, first_name, last_name)** — по нормализованному телефону: если клиент есть — обновить имя/фамилию при необходимости и вернуть id; иначе создать с `telegram_id=NULL`, `phone`, `phone_normalized`, `first_name`, `last_name`.
- **get_client_by_phone(phone)** — поиск по нормализованному телефону (для верификации в боте).
- В существующем **get_or_create_client(telegram_id, ...)** при создании нового клиента по telegram_id по-прежнему заполнять phone/phone_normalized, если передан phone.

### 3. API для тренера (Mini App «Расписание»)

- **GET /trainer/clients?q=...** — уже есть; доработать: поиск в реальном времени по `phone_normalized` (цифры из `q`) и по имени/фамилии (ilike/подстрока). Возвращать и клиентов с `telegram_id=NULL`.
- **POST /trainer/clients** — тело `{ "phone", "first_name", "last_name" }`: создание клиента без telegram_id (get_or_create_client_by_phone), ответ `{ "client_id" }`.
- **POST /trainer/booking** — уже есть: `slot_id`, `client_id`; работает и для клиентов без telegram_id.

### 4. Mini App «Расписание» (schedule-editor)

- В модалке «Записать клиента»:
  - Поле поиска: **real-time** (при вводе запрос GET /trainer/clients?q=...) по телефону и по имени/фамилии.
  - Список результатов: выбор клиента → POST /trainer/booking.
  - Кнопка **«Новый клиент»** → форма: телефон (обязательно), имя, фамилия → POST /trainer/clients → затем с выбранным `slot_id` сразу POST /trainer/booking с полученным `client_id` (или два шага в одном: «Добавить и записать»).

### 5. Клиентский бот: привязка по телефону

- Сценарий «Записаться» / первый вход: если у пользователя ещё нет привязанного client (по telegram_id) — предложить **«Ввести телефон»** (и при желании имя/фамилию для подсказки).
- По телефону ищем **get_client_by_phone(phone)**. Если не нашли — «Клиент не найден» (запись только через тренера).
- Если нашли и у него `telegram_id IS NULL`: отправить **проверочный код** на телефон (SMS или пока заглушка: код в консоль/логи для разработки).
- Пользователь вводит код → при совпадении: **UPDATE clients SET telegram_id = :tid WHERE id = :cid**; сообщить «Профиль привязан».
- Дальше обычный флоу записи (каталог / запись к выбранному тренеру).

### 6. Уведомления и напоминания

- При формировании напоминаний и отмен: если у клиента `telegram_id IS NULL` — не слать push в бота (тренер сам связывается по телефону). В карточке записи в «Мои записи» показывать телефон и пометку «Без бота» / «Не в боте».

### 7. (Опционально) SMS для кода

- Интеграция с SMS-шлюзом для отправки кода верификации; либо временно: код в лог / тестовый режим (ввод любого кода для разработки).

---

## Порядок реализации

1. Миграция: `telegram_id` nullable, `phone_normalized`, unique.
2. get_or_create_client_by_phone, get_client_by_phone в приложении.
3. POST /trainer/clients, доработка GET /trainer/clients (поиск по phone + имя/фамилия, включая клиентов без telegram_id).
4. В schedule-editor: real-time поиск в модалке, кнопка «Новый клиент» + форма, вызов POST /trainer/clients и затем POST /trainer/booking.
5. В клиентском боте: сценарий «Ввести телефон» → поиск клиента → отправка кода → проверка кода → привязка telegram_id.
6. Проверка напоминаний/отмен на наличие telegram_id; пометки в UI для «без бота».

После этого тренер сможет из расписания записывать и существующих (поиск по телефону/имени в реальном времени), и новых по телефону+имени+фамилии без Telegram; позже клиент сможет привязать аккаунт по телефону через проверочный код.

---

## Реализовано

- **П.1–2:** Миграция 0041 (telegram_id nullable, phone_normalized + unique), get_or_create_client_by_phone, get_client_by_phone, attach_telegram_id_to_client.
- **П.3–4:** GET /trainer/clients?q=..., POST /trainer/clients, POST /trainer/booking; schedule-editor: модалка «Записать клиента» с real-time поиском, «Новый клиент» (телефон, имя, фамилия) → POST /trainer/clients → POST /trainer/booking.
- **П.5:** Клиентский бот: при нажатии «Записаться» без привязанного профиля — запрос телефона → get_client_by_phone → при найденном клиенте с telegram_id=NULL выдаётся 4-значный код (пока в сообщении бота + лог сервера), ввод кода → attach_telegram_id_to_client.
- **П.6:** Напоминания не создаются для клиентов без telegram_id (generate_reminders_for_booking); в циклах уведомлений проверка `if not chat_id: continue`. В UI тренера: в расписании (список клиентов при записи) и в «Мои записи» (trainer-bookings) отображается пометка **«Без бота»** для клиентов без telegram_id (client_has_telegram в API).
