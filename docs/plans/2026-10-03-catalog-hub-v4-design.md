# Каталог и хаб v4 — подборки из данных, защита от пустых состояний

Дата: 2026-10-03 · Задача: TASK-148 · Статус: план к утверждению
Макет: [`design/client-hub-catalog-final-v2.html`](../../design/client-hub-catalog-final-v2.html) (v5)

## Зачем

Вкладка «Поиск» должна работать как самостоятельный каталог рынка катания — без записей,
без наполненности тренерами, и при этом быть виральным продуктом, которым делятся.
Хаб должен собираться из данных клиента, а не из ссылок. Две угрозы, от которых защищаемся:

1. **Пустые состояния.** Чип категории с нулём («Школы · 0»), блок без наполнения, серый
   плейсхолдер фото — всё это обещание без содержания. Правило: что без данных — не рендерится.
2. **Контент-машина.** «Подборки» и «свежее», которые кто-то должен наполнять руками,
   умрут через неделю. Всё новое в хабе собирается из существующих данных.

## Решения

| Решение | Выбор | Отклонено |
|---|---|---|
| Чип категории без данных | Не рендерится. Ноль школ — нет чипа школ. Ноль категорий — нет ленты | «Честный ноль» (v4): чип виден с нулём |
| Место без фото | Бесфотошная карточка: иконка типа на цветной плашке | Серый плейсхолдер; скрывать место |
| Подборки | Шесть пресетов-фильтров (таблица), каждая — ссылка в каталог с фильтром | Ручные подборки; контентные сторис |
| «Свежее в каталоге» | Убрано (нечем честно наполнять) | Оставить как контент-блок |
| Хаба-«сторис» | Не вводим | Кружки в стиле Instagram |
| Лента категорий | Пять категорий, счётчики, рендер только при данных | Категории-нули |
| Стиль | Существующие токены theme.css + 4 новых токена типов | Перерисовка палитры; чужие цвета из заметок специалиста |

## Данные, на которых стоим (уже в системе)

- Типы площадок: `ice, outdoor, gym, choreo, pool, other, shop` — `src/shared/venue_types.py`.
  `shop` скрыт в ленте по умолчанию (`DEFAULT_HIDDEN_VENUE_TYPES`), чип «Магазин» — в фасетах.
- Удобства: `skate_rental`, `skate_sharpening`, `retail`, `repair` + `SHOP_AMENITY_KEYS`
  (`src/application/arena_profile.py`). Поиск по услуге: «заточка» → `skate_sharpening`
  (`arena_public_use_cases.py:1402`).
- Подборки-ссылки: `/c/{город}?t=<тип>&w=<окно>` (`docs/product-knowledge/public-place-pages.md`).
- Окна: `when=auto|today_evening|today|tomorrow|weekend|any` (`src/application/ice_time_windows.py`).
- Тиры A/B/C: C — только адрес, приглушённая карточка (`compute_data_tier`).
- Фото: тренерские арены без фото уже исключены из клиентского поиска (SQL по `media`,
  `arena_public_use_cases.py`); у импортированного каталога фото может не быть.
- Хаб уже рендерит: ice teaser, streak, ближайшая запись, основной тренер, панель абонемента,
  upcoming, сохранённые тренеры (`static/webapp/client-home-main.js`).

## Контент подборок (финальный)

| Пресет | Фильтр | Рендер, когда |
|---|---|---|
| Сегодня вечером | `today_evening`, ice+outdoor | сеансов в окне > 0 |
| Крытые | `venue_type=ice` | катков > 0 |
| Открытые | `venue_type=outdoor` | катков > 0 (сезонно) |
| Бесплатно | цена сеанса = 0 | бесплатных сеансов > 0 |
| Заточка | `skate_sharpening` (ice+shop) | мест > 0 |
| Магазины | `venue_type=shop` | магазинов > 0 |

Правила рендера: карточка — только при счётчике > 0; секция «Подборки» — только при ≥ 2 живых
карточек; арт без фото — цветная плашка типа. Порядок: по счётчику/сезонности.

## Приёмочные критерии

1. **Чипы по данным.** Лента категорий рендерит только категории со счётчиком > 0 в текущем
   городе и скоупе. Все нули → лента отсутствует. Проверка: город с 0 катков, 0 тренеров;
   город с 2 магазинами и больше ничем.
2. **Без фото — без фото-блока.** В каталоге, на карте и в подборках место без `media`
   рендерится бесфотошным вариантом (иконка типа на плашке). Ни одного серого плейсхолдера.
3. **Подборки в хабе.** Шесть пресетов; каждая карточка ведёт в каталог с применённым
   фильтром (`/c/…` или deep link `startapp`); карточка и секция рендерятся только при данных.
4. **«Сегодня на льду».** 2–3 ближайших сеанса из live-данных; нет сеансов — нет блока.
   Не дублирует существующий ice teaser: teaser остаётся как есть, блок — дополнение.
5. **Ничего не сломано.** Существующие блоки хаба и каталога не изменены; `pytest -m collective`
   и JS-тесты (399) зелёные; e2e каталога проходит.
6. **Состояния покрыты тестами.** Для каждой подборки: 0, 1, N. Категория-ноль, место без
   фото, пустой результат фильтра, пустой город.
7. **Токены.** Новые токены типов — переменные в `theme.css`, существующие не переопределены;
   `G-P1` (нарушения дизайн-системы) не растёт.

## Слайсы

- **S1 — чипы по данным (каталог).** Фасеты/лента категорий рендерятся от счётчиков
  (`> 0`). Список категорий для ленты — из тех же запросов, что фасеты. Тесты: 0/1/N.
- **S2 — бесфотошная карточка.** Вариант карточки места без фото: каталог, карта, подборки.
  Регрессия: карточки с фото не меняются.
- **S3 — подборки в хабе.** Секция «Подборки» + генерация ссылок с фильтрами на существующем
  механизме `/c/`. Решение открытого вопроса: «ночной лёд» — окно или фильтр по часу.
- **S4 — «Сегодня на льду».** Блок из live-сеансов; рендер по данным.
- **S5 — токены типов.** 4 переменных в `theme.css`; прогон палитры; проверка G-P1.

## Риски и «не поломать»

- **Хаб — самая нагруженная поверхность.** Новые секции монтируются после существующих
  блоков и только при данных; существующий HTML/JS не переписывается, классы новые.
- **Сезонность «Открытые».** Летом outdoor = 0 → карточка исчезает сама (это и есть защита).
- **Счётчики должны быть дёшевы.** Переиспользовать фасетные подсчёты каталога; новых тяжёлых
  запросов не вводить. Если счётчик дорогой — секция не рендерится, а не считается в ущерб.
- **Карта.** Бесфотошность на пины не влияет (пин — время/тип, не фото); карточки карусели
  подчиняются правилу №2.
- **Тренерское приложение и B2B.** Не затрагиваются; токены только добавляются.
