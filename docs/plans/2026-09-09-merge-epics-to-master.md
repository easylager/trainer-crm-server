Это runbook на этот кат, не вечная архитектура. После мержа документ уезжает в `docs/archive/`.

## Почему нельзя «просто смержить обе в master»

1. **Вилка Alembic.** Оба поезда ветвятся от `0198_ice_scrape_runs`:
   - региональный: `0199_ice_city_interest`
   - premium: `0200_client_share_events` (пропуск 0199 **осознанный**, см. комментарий в файле миграции)
   Нужен `alembic merge` → `0201`, иначе `upgrade head` на проде упадёт.
2. **Один набор горячих файлов льда правили обе линии** (17 путей): `ice.html`, `ice-tab.js/css/model.js`, `ice-map*.js`, `arena_public_use_cases.py`, `public_arenas.py`, `models.py`, `parsers.py`, тесты. Автомерж здесь врёт.
3. **UI регионального «Льда» старше premium.** Там эмодзи на чипах, сегмент Список/Карта, `MAP` как в TASK-082. Premium уже: список первым, карта в один тап, без эмодзи, токены темы. Победитель UI — **premium**. С регионального забираем поведение, не внешний вид.
4. **Данные не в git.** Сиды и фото гонялись в локальный `trainer_crm`. Скрипты с `--apply` **отказываются писать в Railway** (`CLOUD_DB_MARKERS`). Локальные `uploads/arenas/` не задеплоятся. На проде файлы должны уйти в S3.
5. **PDEC-006.** `release/client-premium` не пушилась из-за CI (`on.push: release/**`). Не оживлять длинный remote-поезд: один PR в `master`.
6. **Незакоммиченное, без которого прод снова соврёт в ценах:** в ice-regional `prices_already_minor: true` на batch C (Островец / Орша / Могилёв). Без этого нормализатор умножит копейки второй раз.

## Принцип сборки

Один интеграционный кат, не два деплоя подряд.

База = **client-premium** (больший UI-поверхность, «Лёд» уже тот, который должен увидеть клиент). В неё вливается **ice-regional-parsers**. Конфликты льда режем вручную по правилу ниже. Потом один PR в `master`.

Не делать: ice-discovery → master, потом premium. Пользователь увидит промежуточный «Лёд» без премиума и без регионов.

```
origin/master
  └── origin/release/ice-discovery
        ├── release/client-premium     ← база интеграционной ветки
        └── feat/ice-regional-parsers  ← вливаем сюда
              └── release/prod-cut-YYYYMMDD  → PR → master → Railway
```

## Правило конфликтов «Льда»

| Файл / тема | Берём |
|---|---|
| `ice.html`, `ice-tab.css`, оболочка, чипы без эмодзи, список→карта (TASK-103) | premium |
| Пикер городов: поиск, популярные, только города с катком/тренерами, «скоро добавим» + `POST /ice/interest` | regional (в премиум-вёрстку) |
| Скрыть «Покататься», если в городе нет живого катка; «Группы» hidden пока нет набора | regional |
| Фильтр услуг на линзе «Тренеры» | уже есть в premium (TASK-084); не откатывать на regional |
| `starts_at_utc > now` (PDEC-005) во всех линзах | premium; проверить, что regional SQL его не затрёт |
| `default_registry()` | Минск из premium **включая** `MinskSpeedOvalParser` + batch A–D из regional |
| `0199` + `0200` | оба + merge-ревизия `0201` |
| Незакоммиченный `0199` в worktree `release/by-prod` | не копировать руками; взять из regional при мерже |

Открытый PR #56 (`TASK-082` → ice-discovery) **не мержить отдельно**: нужные куски уже в regional, UI — в premium.

## Последовательность

### 1. Локальная интеграционная ветка

От `release/client-premium`:

```text

git merge feat/ice-regional-parsers
```

Разрешить 17 пересечений по таблице выше. Сразу:

```text

```

### 3. Один PR в master

Пушить **только** интеграционную ветку. Не пушить `release/client-premium` (PDEC-006 / минуты CI).

### 4. Деплой кода, затем данные — в одном окне

Порядок на проде обязателен. UI льда без сидов = пустой таб.

1. Backup Postgres (уже есть ночной dump; перед катом — ручной, если окно не совпадает).
2. Задеплоить master. Alembic до `0201`.
3. Проверить, что `notification_service` поднял `run_ice_ingest_scheduler_loop` (на master его нет, после ката — есть).
