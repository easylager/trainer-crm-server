# Места от людей: заявки, модерация, страны

Дизайн утверждён владельцем 2026-10-28. Решение — PDEC-028.

## Зачем

Люди просят добавлять места сами: арены в Уфе с ценами, ледовые магазины, города,
которых у нас нет. Каталог должен расти за счёт людей, а не ручного ввода по одной
точке. Спрос из России подтверждён (тренер из Питера, заявки из Уфы). Telegram у российских пользователей работает (владелец, 2026-10-28).

## Принципы

- Любой может предложить место с минимальной детализацией, даже в городе, которого нет.
- Публикуется только после модерации. Модератор правит, дописывает, пишет автору.
- Контакт автора необязателен.
- Город — данные, а не код: одобренный город появляется на сайте без программиста.

## 1. Заявка глазами человека

**Входы** (одна форма для сайта и Mini App): «Предложить место» в шапке; «Нет вашего
города? Добавьте» у карты страны и в пустых состояниях; «Дополнить» на карточке места.

**Шаги** (по экрану, обязательного минимум):

1. **Что это?** Четыре плитки с иконками Phosphor: крытый каток · открытый каток ·
   магазин / заточка / прокат · школа / секция.
2. **Где?** Город с автоподсказкой: сначала наши города, затем геокодер OSM
   («Уфа, Башкортостан, Россия — новый город»; не нашёлся — свободный текст).
   Название, адрес по желанию, булавка на мини-карте.
3. **Что знаете?** Всё необязательно, поля по типу:
   каток — цены (взрослый / детский / прокат, валюта по стране), часы или сеансы
   текстом, телефон / сайт; магазин — чипы «заточка / прокат / продажа», часы;
   школа — чипы «фигурное / хоккей», возраст, ссылка. Внизу «Что ещё знаете».
4. **Связь.** Необязательное поле «Email или Telegram — если не против, что мы уточним».

Минимум: тип + город + название или пара слов описания.
После отправки: «Спасибо, заявка у нас»; с контактом — «напишем, когда место появится».
Сроков не обещаем. Антиспам: honeypot + лимит по IP, без капчи.

## 2. Данные и жизненный цикл

**`place_suggestions`** — сырая заявка, а не арена: тип; `city_id` или новый город
(название, страна, координаты из геокодера); название, адрес, булавка; поля типа (JSON);
контакт; источник (`site` / `miniapp`, автор Mini App); `target_arena_id` для «Дополнить».

**Статусы:** `new` → `needs_info` → `approved` · `rejected` (причина: спам, не про лёд,
закрылось) · `duplicate` (склейка с существующим местом, данные переносятся выборочно).

**Одобрить** — одна транзакция: найти или создать город (страна, координаты, активен),
место (`venue_type`, `is_confirmed`), публичную карточку. Цены заявки — «типичная цена»
места (нужно новое поле: сейчас цены есть только у сеансов), подпись источника
«по данным посетителей», без даты. Заявка остаётся в истории как источник.

**Новые типы:** `school`. `outdoor` и `shop` уже есть в `src/shared/venue_types.py`.

**Контакт** хранится до закрытия заявки + 30 дней, затем стирается.

**Город без расписания** — новый публичный уровень (поправка PDEC-018): светлая точка на
карте страны, страница города с карточками мест (часы, цена, телефон),
`schedule_mode=phone` — «Расписание пока не знаем — позвоните». Скрытие Москвы до
≥4 арен со свежим расписанием остаётся: это порог качества конкретного города.

## 3. Модерация

**Админ-бот:** «Новая заявка №37 · Крытый каток · Уфа (новый город) · есть цены и контакт»,
кнопки «Открыть» и «Одобрить как есть» (вторая — только без похожих мест рядом и при
наличии названия и города).

**Админский Mini App, экран «Заявки»:** вкладки «Новые / Ждём ответа / Закрытые»,
новые города выделены. Карточка заявки:

1. Карта: булавка + наши места в радиусе 1 км.
2. «Похоже на»: близкие по названию / адресу места города, «Это дубль — перенести
   данные туда» с выбором полей.
3. Редактируемые поля будущей карточки, для нового города — название, страна, точка.
4. Переписка: Telegram (автор из Mini App или указал ник) — через клиентского бота,
   ответы возвращаются в ленту. Email — пока только копирование адреса: исходящей
   почты нет. «Написать» переводит заявку в `needs_info`.

Кнопки: «Одобрить» · «Нужно уточнить» · «Отклонить». После одобрения автору с контактом:
«Ваше место „…“ появилось в Glide» + ссылка. Модерирует пока только владелец; роль
модератора по стране / городу — когда появятся помощники.

## 4. Структура сайта

- `/by/`, `/ru/` — страницы стран: карта, список городов, «лёд сегодня».
- `/` — страна посетителя по IP (если есть у нас, иначе BY), переключатель стран.
- `/c/{город}`, `/p/{город}/{место}` не меняются; в крошках появляется страна.
- `cities` получает координаты и регион; `_BY_CITY_ROWS` из `catalog_home_page.py`
  переносится в БД; фильтры `== "BY"` → «страна страницы».
- Карта — рисованный SVG как сейчас; контуры стран в `data/` по файлу на страну.
  Точки: полная (есть расписание), светлая (без расписания), «+» «Добавить город».
- Россия: города кластерами по регионам + список городов по алфавиту с числом мест.
- Mini App: форма и «Дополнить»; старый «Сообщить об ошибке» (текст в поддержку)
  переводится на `place_suggestions`.

## 5. Порядок запуска (каждый этап — волна релиза)

1. Заявки и модерация: таблица, форма (сайт + Mini App), экран заявок, уведомления,
   переписка через Telegram. Одобренные новые города видны через `/c/{город}`.
2. Города как данные: координаты, перенос BY в БД, уровень «город без расписания».
3. Страницы стран: `/by/`, `/ru/`, карта России, переключатель на главной.
4. Рост: «Дополнить» на карточках, сообщение автору «место появилось».
