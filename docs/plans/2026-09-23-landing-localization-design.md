# Лендинг Glide — локализация по городам и рынкам

**Дата:** 2026-09-23
**Состояние:** модель согласована, реализация отложена (сначала — правки контента)
**Действующий прототип:** `docs/plans/assets/2026-09-22-landing-hero-proto/prototype-v2.html`

## Зачем документ

Запуск идёт по городам Беларуси и по России. Посетитель приходит из конкретного
города, и страница обязана это учитывать. Решения записаны **до** реализации,
потому что ошибка здесь переделывается дороже всего: от неё зависят URL-схема,
рендеринг и структура рекламных кампаний.

Два вывода, оба ломают текущий макет:

1. **В 13 городах из 15 — ровно одна арена.** Стена арен, на которой построен

2. **В 9 городах из 15 сегодня ноль сеансов.** Весь герой построен на слове
   «сегодня». Для 60% живых городов первый экран будет пустым.

## Что уже есть в коде

Изобретать почти нечего:

- `src/shared/ip_geo.py` — IP→страна на локальной базе `geoip2fast`, без сетевых
  вызовов и без разрешений. `SERVED_MARKET_COUNTRIES = {BY, RU, RS}`. Уже
  используется в Mini App (`webapp.py:2062`, `:2883`), **но не на лендинге**.
- Манифесты рынка `static/landing/verticals/ice.by.json` и `ice.ru.json` —
  копирайт уже разнесён по рынкам.
- `GET /api/public/ice/arenas` умеет `city_id`, `bbox`, `near`
  (`public_arenas.py:62`); есть `/ice/cities` и публичная страница
  `/ice/{city}/today` (`public_ice_page.py:52`).

**Что архитектурно не так:** `landing_market: str = "by"`
(`src/shared/config.py:203`) — переменная окружения. Один деплой отдаёт один
рынок всем посетителям. Это и есть корень проблемы.

## Решения

| # | Решение | Почему |
|---|---------|--------|
| L1 | Три режима города, вычисляемые из живых данных | Город сам переезжает между режимами по мере роста, без правок вёрстки |
| L2 | Окно времени адаптивное: нет сеансов сегодня → ближайшие 7 дней | Иначе 9 городов из 15 встречают пустотой |
| L3 | Рамка — рынок, а не страна: BY → «Лёд Беларуси», RU → «Лёд Петербурга» | 12 арен на страну выглядят жалко, 12 арен в городе — плотно и честно |
| L4 | **Город в пути URL:** `/minsk`, `/spb`, `/orsha` | Реклама таргетится на городскую страницу, органика по «каток <город> расписание», партнёру даётся «его» ссылка |
| L5 | Город без живого льда → **национальная картина страны** | Решение владельца. Человек видит масштаб сети целиком, а не пустой город |
| L6 | Явный выбор никогда не перебивается автоопределением | Иначе ссылка из рекламы по Гродно покажет Минск |
| L7 | Городские страницы рендерятся на сервере или пререндерятся | Иначе краулер видит пустой каркас и городские URL теряют половину смысла |

### L1 — три режима

| Режим | Условие | Первый экран | Оффер тренеру |
|---|---|---|---|
| **Рынок** | 3+ арены | Стена арен (текущий герой) | «Вас находят там, куда и так идут» |
| **Каток** | 1–2 арены | Одна арена крупно + её расписание | «Единственный каток города — и вы единственный тренер на нём» |
| **Скоро** | 0 живых арен | Национальная картина страны (L5) | «Приведите свою арену — подключим» |

Режим — функция от данных, не от списка городов. Компонент для режима «Каток»
уже существует: это крупная карточка арены с ростером из секции «Тренерам»
(`.acard--lead` в prototype-v2).

Сегодня по этому правилу: **Рынок** — Санкт-Петербург и Минск; **Каток** — все
остальные 13 городов; **Скоро** — Витебск и прочие города с ареной в каталоге,
но без живого расписания.

### L6 — цепочка определения

По убыванию приоритета:

1. Явный выбор — город в пути URL или сохранённый в localStorage;
2. GPS, если разрешение **уже** выдано (без промпта) → ближайший город;
3. IP → страна → город по умолчанию рынка (BY → Минск, RU → Санкт-Петербург);
4. Не определилось → домашний рынок BY.

Автоопределение решает только, куда редиректить с `/`. Оно не вмешивается ни
в один явный адрес.

## Граница честности

Фото арен разнородны: 99 снимков в `media`, ширина от **200 до 5472** px,
медиана около 1400. Правило для витрины: **в крупную врезку идёт только media
шириной ≥1200**, остальное — в мелкую карточку либо нейтральный блок. Иначе
качество первого экрана зависит от того, чей снимок подтянулся. В prototype-v2
это уже применено: ТЦ Замок берётся hero-вариантом 1600×554, а не card-вариантом
393×372.

## Что осталось решить

- **Слаги городов.** `/spb` или `/sankt-peterburg`; как быть с агломерациями —
  в базе город называется «Санкт-Петербург/ЛО» и «Москва/МО».
- **Где живёт порог режима** (3 арены) — в конфиге или в коде.
- **Карта для режима «Рынок» на RU** — карта районов Петербурга, а не России;
  источник геометрии не выбран.
- **Что именно показывает «национальная картина»** для посетителя из пустого
  города: карту со всеми живыми городами, ближайший город отдельной строкой,
  или и то и другое.
