# Релиз `release/18.10.26` — пайплайн до клиента

Дата: 2026-10-18. Ветка: **`release/18.10.26`**. Главная пользовательская фича поезда — **«Собрать компанию»** (компания на один сеанс льда, код `ice_company`). Остальное в том же кате — публичный футер, региональные ассеты каталога, мелкие правки главной и перф публичных фото.

Это **не** вечная архитектура: после выката и стабилизации актуальные чеклисты остаются в `docs/ops/`, продукт — в `docs/product-knowledge/ice-company.md`, этот файл можно увезти в `docs/archive/`.

Визуальный черновик «кто что видит по времени» (включая будущие TASK 281–288): [`design/prototypes/2026-10-17-company-on-ice-timeline.html`](../../design/prototypes/2026-10-17-company-on-ice-timeline.html). **На прод в этом релизе уезжает то, что уже в коде ветки**, не весь сценарий прототипа.

---

## 1. Что считаем «релизом»

| Слой | Смысл |
|------|--------|
| **Поезд** | Долгоживущая или релизная ветка (`release/18.10.26`), куда сливаются фичи до готовности ката |
| **Кат** | Merge поезда в **`master`** одним PR (или согласованным набором PR), после зелёного CI |
| **Прод** | Railway деплоит сервисы с `master`; схема БД — `alembic upgrade head` на прод-Postgres |
| **Включение фичи** | Для ice company — **отдельный шаг**: `ICE_COMPANY_CITY_IDS` на API и `notification_service`. Код на проде без флага = кнопки нет, создать компанию нельзя; старые `/k/{code}` открываются |

Агент **не** мержит в `master`, **не** меняет Railway Variables и **не** шлёт release comms без явного решения человека.

## 2. Пайплайн: от ветки до продакшена

```text
feat/*  ──PR──►  release/18.10.26
                      │
                      │  CI (tests.yml), ручной «Руками» по задачам
                      ▼
                 PR → master  (release cut)
                      │
                      ├── Railway: API (+ static /webapp, /k, миграции при старте)
                      ├── Railway: клиентский бот (inline, callback ic:)
                      └── Railway: notification_service (run_ice_company_loop)
                      │
                      ▼
                 Env: ICE_COMPANY_CITY_IDS=…  (по городам, когда готовы)
                      │
                      ▼
                 (опционально) broadcast_release_comms — см. §5
```

**База для сравнения с продом:** `origin/master`. На момент подготовки документа поезд — ~9 коммитов впереди master (ice company, футер, каталог).

**Миграция фичи:** `0237_ice_companies` (таблицы компании, расширение `catalog_consumer_events` новыми `kind`). Head линейки — проверить `alembic heads` перед катом.

**Сервисы, без которых фича «мертва»:**

| Сервис | Зачем |
|--------|--------|
| API | `POST/GET /api/public/ice-companies`, `/k/{code}`, `/webapp/ice-company`, флаг `ice_company` на карточке арены |
| Клиентский бот | Inline «каток в чат», callback «Иду / Не могу», chosen_inline_result |
| `notification_service` | Цикл `run_ice_company_loop`: синхронизация сеанса, протухание, **правка inline-карточек в чатах** |

Тренерский бот и рассылка тренерам для этой фичи **не** обязательны.

Подробный чеклист после merge: [`docs/ops/ice-company-launch.md`](../ops/ice-company-launch.md).

## 3. Гейт перед merge в `master`

1. **CI зелёный** на ветке поезда (`pytest`, JS-тесты по затронутым пакетам).
2. **Миграции:** локально `alembic upgrade head` на чистой БД; на поезде один head, без вилки.
3. **Ice company:** `tests/api/test_ice_company_api.py` и связанные unit-тесты.
4. **Юридический черновик** не блокирует деплой кода, но блокирует **массовую рассылку** и публичное обещание в коммах, пока юрист не окнул: [`2026-10-16-ice-company-pdn-draft.md`](2026-10-16-ice-company-pdn-draft.md).
5. **Решение по городам:** список `city_id` для первого включения записан в runbook (не «угадывать по локальному `.env`**).

## 4. Как клиент узнаёт о «Собрать компанию» (каналы и момент)

Фича задумана как **органический и шаринговый** поток, не как push всей базе в день деплоя.

### 4.1. Пока город выключен (`ICE_COMPANY_CITY_IDS` пуст или без этого `city_id`)

| Кто | Что видит |
|-----|-----------|
| Все в этом городе | Как сейчас: «Позвать», шаринг сеанса, без кнопки «Собрать компанию» |
| Кто открыл старую ссылку `/k/{code}` | Страница компании и ответы работают |

### 4.2. Сразу после добавления `city_id` в флаг (без Telegram-рассылки)

| Момент | Канал | Кто узнаёт |
|--------|--------|------------|
| T+0 | **Мини-приложение → карточка арены** с выбранным сеансом | Пользователь видит **«Собрать компанию»** рядом с «Позвать» (`ice_company: true` в API карточки) |
| T+0 | **Deep link** `startapp=company_{session_id}` → `/webapp/ice-company` | Тот, кому прислали ссылку / кто попал из рекламы внутри бота |
| T+1… | **Шаринг из шита** (variant `company`) | Друзья в Telegram — **inline-карточка с фото льда** в чате; бот в группу не добавляется |
| T+1… | **Публичная страница** `https://…/k/{code}` | Гости из WhatsApp / Instagram / браузера; превью `og.png` |
| Постоянно | **Обновление той же карточки в чате** | Участники видят новые имена без нового сообщения (`notification_service` + `edit_message`) |

**Чего нет в текущем tick планировщика (важно для ожиданий):**

- Личные DM «за день / за час до катка» **не отправляются** — все `pending` напоминания помечаются `skipped` (сбор живёт на карточке в чате).
- Код follow-up организатору и weekly в репозитории есть, но **в прод-тике не вызывается** вместе с этим skip.

То есть **массового «мы запустили фичу» от бота по расписанию нет** — только точечные DM при отмене сеанса катком (ветка cancel notice), если сработает.

### 4.3. Осознанная рассылка всей базе (release comms)

По правилам [`docs/release-comms/README.md`](../release-comms/README.md):

| Нужно сообщение | Не обязательно |
|-----------------|----------------|
| Новый заметный экран / кнопка в Mini App | Включили фичу в одном городе для эксперимента |
| Меняется оплата, записи, имя бота | Бэкенд и флаг без UX для остальных городов |

**Рекомендация для 18.10.26:**

1. **Кат в master** — можно **без** рассылки: у большинства городов кнопки ещё нет.
2. **Первый город в флаге** — по умолчанию **без** broadcast; смотрим `company_created` / `card_shared` в `catalog_consumer_events`.
3. **Рассылка clients** — когда включаем фичу **для всей аудитории каталога** (или для крупного города с явным маркетингом): черновик `docs/release-comms/YYYY-MM-DD-ice-company.clients.md` (ещё не создан), preview → dry-run → send **за 5–15 мин до** деплоя, если в тексте обещаем то, что уже на проде.

Тренерам писать **не нужно**, если в их кабинете ничего не меняется.

## 5. Порядок действий человека (release cut + включение)

### Фаза A — код на прод (фича выключена)

1. PR `release/18.10.26` → `master`, CI, merge.
2. Дождаться деплоя Railway (API, клиент-бот, `notification_service`).
3. Проверить миграцию: `0237_ice_companies` на прод-БД.
4. Убедиться, что **`ICE_COMPANY_CITY_IDS` пуст** (или не задан) — регрессии нет, smoke каталога/льда.
5. В логах `notification_service` нет постоянных `ice_company tick failed`; цикл стартует вместе с ботом.

### Фаза B — включение города

1. Согласовать `city_id` (см. таблицу `cities` на проде, не копировать с dev вслепую).
2. Выставить **одинаковый** `ICE_COMPANY_CITY_IDS` на **API** и **`notification_service`**; redeploy/restart.
3. Пройти [`ice-company-launch.md`](../ops/ice-company-launch.md) § «20 минут руками».
4. Зафиксировать в этом файле (ниже) дату включения и список городов.

### Фаза C — коммуникация (по решению)

1. При необходимости — release comms (§4.3).
2. Внешние каналы (Instagram, чат комьюнити) — **после** фазы B, иначе ссылка ведёт на UX без кнопки.

## 7. Что ещё в поезде (не ice company)

Кратко, чтобы не путать релизную коммуникацию:

| Тема | Эффект для клиента |
|------|---------------------|
| Публичный футер, лёгкая motion | Сайт `/c`, `/p`, legal |
| Региональные фото/магазины в `data/catalog` | Нужен импорт на прод, если обещаем в шаринге — см. [`catalog-share-launch.md`](../ops/catalog-share-launch.md) |
| Главная каталога после 21:00 Минск | Дефолт «завтра» |
| Перф публичных фото | Быстрее повторные визиты, без отдельного анонса |

Отдельная рассылка по этим пунктам — только если маркетинг хочет; иначе достаточно тихого выката.
