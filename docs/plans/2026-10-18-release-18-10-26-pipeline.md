## 3. Выкат

### Фаза A — код (всё новое выключено флагами, кроме шкалы, билетов к записи и страницы катка)

1. Merge PR #195 → `master`, дождаться деплоя Railway: API, клиентский бот, `notification_service`.
2. Миграции на проде: `alembic current` → `0244_minsk_load_characters`.
3. Smoke: `/p/minsk/zamok` — «110 мест» на сеансах и кнопка «Купить билет онлайн»; `/p/minsk/chizhovka` — полоски; карточка катка в Mini App — то же.
4. Логи `notification_service`: нет постоянных `ice_company tick failed`, `[ice_forecast_loop] started`.

### Фаза B — включение (Railway Variables, id из прод-таблицы `cities`, не из dev)

| Переменная | Где | Значение |
|------------|-----|----------|
| `FOR_YOU_CITY_IDS` | API | id Минска |
| `ICE_COMPANY_CITY_IDS` | API **и** `notification_service`, одинаково | id Минска (после юриста) |
| `ICE_FORECAST_ENABLED` | `notification_service` | `true` (с 26 октября, TASK-331) |

После смены — redeploy/restart сервисов.

### Фаза C — руками

1. **Партнёр в подборке:** админский Mini App → Справочники → «Для вас» → Минск → позиция 1 → найти магазин → «Закрепить». Магазин должен быть в каталоге.
2. **Компания:** пройти [`ice-company-launch.md`](../ops/ice-company-launch.md) § «~20 минут руками».
3. **Старт сезона** (сразу после релиза, решение владельца):
   ```bash
   python3 scripts/send_ice_forecast.py --campaign season_start --dry-run
   python3 scripts/send_ice_forecast.py --campaign season_start --to <свой telegram_id>
   python3 scripts/send_ice_forecast.py --campaign season_start
   ```
   Повторный запуск не шлёт второй раз (журнал `client_broadcast_log`).
