# Приёмка: «золотой» сценарий клиента (staging)

**Цель:** клиент при нормальной сети не застревает без объяснения: понятные шаги, кнопки и тексты от первого входа до записи или заявки и до напоминания о занятии.

**Главный сценарий продукта (A):** каталог → выбор тренера → **запись на слот** (Mini App) → сообщение об успехе → (по цепочке) подтверждение тренером → **напоминание** за 24 ч / 2 ч до занятия.

**Альтернатива (B):** заявка на подбор тренера → отклик / напоминание без отклика.

Источники текстов: `src/bot/messages.py`, `static/webapp/book.html`, хендлеры `src/bot/handlers/client_handlers.py`, циклы `src/bot/notification_loops.py`.

---

## Предусловия staging

| Проверка | Зачем |
|----------|--------|
| `WEBAPP_BASE_URL` = `https://…` (клиентский и API бота видят тот же прод/стейдж URL) | Mini App каталога и записи |
| В БД есть город, услуга, **активный** тренер со слотами на ближайшие дни | Непустой каталог и слоты в `book` |
| Запущены **клиентский бот** и **notification_service** (напоминания не шлёт сам `client_app`) | Напоминания 24h/2h |
| Тестовый Telegram-аккаунт клиента (не тренер) | Чистый путь |

---

## Сценарий A — запись через каталог (основной)

### Шаг 1. Первый вход

| Действие | Ожидание |
|----------|----------|
| Пользователь отправляет `/start` (без payload) | Сообщение: *«Привет! Здесь можно найти тренера и записаться на занятие. Все разделы — в меню слева от поля ввода. Подробнее: /guide»* (`CLIENT_START_WELCOME`) |
| Меню команд (слева от ввода) | Есть **Помощь**, **Тренеры и запись**, **Мои заявки и отклики**, **Мои записи**, абонементы/сертификаты — см. `client_app.py` `set_my_commands` |

**Критерий:** пользователь видит, куда нажимать дальше (меню + `/guide`).

---

### Шаг 2. Каталог (HTTPS)

| Действие | Ожидание |
|----------|----------|
| Команда `/settings` или пункт меню **«Тренеры и запись»** | Текст: *«Выберите город, услугу, арену и тренера. Нажмите кнопку ниже.»* + кнопка **«Тренеры и запись»** (Web App → `/webapp/catalog`) |
| Открыть Mini App, пройти фильтры (город → услуга → при необходимости арена), открыть карточку тренера | Карточка с данными тренера; есть **«Записаться»** (и при необходимости заявка — см. UI каталога) |

**Критерий:** без выбора города/услуги бот не ведёт в пустой тупик без текста (ошибки — `CLIENT_ERROR_NO_CITIES` / `CLIENT_ERROR_NO_SERVICES` и т.д.).

---

### Шаг 3. Запись: бот → Mini App «Записаться»

| Действие | Ожидание |
|----------|----------|
| В каталоге (или после выбора тренера в сессии) нажать **«Записаться»** (callback `book`) | Сообщение с текстом **«📅 Выберите время»** + список слотов в тексте *или* (на HTTPS) блок про выбор в Mini App (`CLIENT_BOOK_CHOOSE_SLOT` + `CLIENT_BOOK_WEBAPP_FOOTER`) |
| Нажать кнопку **«Записаться»** с Web App | Открывается `/webapp/book?trainer_id=…` |

Если клиент ещё не создан в БД по Telegram, возможен сценарий привязки по телефону (`CLIENT_LINK_PHONE_PROMPT`) — для «золотого» пути заранее убедитесь, что клиент уже есть (повторный `/start` после первой записи или заранее созданная запись).

---

### Шаг 4. Mini App `book.html`

| Действие | Ожидание |
|----------|----------|
| Загрузка слотов | Заголовок вида *«Записаться к {имя}»*, неделя, слоты |
| Выбрать слот | Экран формы: телефон, комментарий, **«Отправить заявку»** |
| Ввести валидный телефон, отправить | Экран успеха: *«✅ Заявка отправлена. Дождитесь подтверждения от тренера — мы сообщим в боте.»* + подсказка про **«Мои записи»** (как в `book.html`) |
| **«Закрыть»** | Закрытие Web App (`tg.close`) |

**Критерий:** при ошибке сети/валидации — `alert` с понятным текстом, не «пустой» экран без кнопки «назад» (есть «Выбрать другое время»).

---

### Шаг 5. После записи в боте

| Событие | Ожидание (типично) |
|---------|---------------------|
| Запись создана со статусом pending | В чат может прийти сообщение в духе успешной записи (`CLIENT_BOOK_SUCCESS` / цепочка из хендлера бронирования — сверить с фактическим ответом API после `POST /client/booking`) |
| Клиент открывает **«Мои записи»** | При HTTPS: интро + кнопка Web App `client-bookings`; в приложении — список, статус «Ожидает подтверждения тренера» (`CLIENT_MY_BOOKINGS_STATUS_PENDING`) |

---

### Шаг 6. Подтверждение тренером (вне клиента, но для сквозной приёмки)

| Действие | Ожидание у клиента |
|----------|---------------------|
| Тренер подтверждает запись | Сообщение *«✅ Тренер подтвердил занятие …»* (`CLIENT_BOOKING_CONFIRMED_BY_TRAINER`) |

---

### Шаг 7. Напоминания о занятии

Запускается **`notification_service`** (интервал опроса напоминаний см. `REMINDER_INTERVAL_SEC` в `notification_loops.py`).

| Событие | Ожидание |
|---------|----------|
| За ~24 часа до начала слота | *«⏰ Напоминаем: у вас занятие {date} ({day}) в {time}, {duration} мин. … зайдите в «Мои записи»…»* (`CLIENT_REMINDER_24H`) |
| За ~2 часа | Аналогично (`CLIENT_REMINDER_2H`) |

**Приёмка:** для теста удобно слот «через 25 часов» и «через 3 часа» с подправленным временем в БД **или** ожидание цикла на стейдже; зафиксировать факт получения обоих видов или отметить дефект.

---

## Сценарий B — заявка (когда в каталоге никого нет или осознанно тестируем заявку)

| Шаг | Ожидание |
|-----|----------|
| В каталоге: **«Оставить заявку»** (футер/пустой список), заполнить комментарий или пропуск | *«Заявка принята. Когда появится подходящий тренер — напишем вам.»* (`CLIENT_REQUEST_SUCCESS`) |
| Тренер откликается | *«📩 По вашей заявке откликнулся тренер…»* + кнопка просмотра откликов (`CLIENT_RESPONSE_NOTIFICATION`, `CLIENT_RESPONSE_BUTTON_VIEW`) |
| Долго нет отклика (фоновый цикл) | *«Пока по вашей заявке никто не откликнулся…»* (`CLIENT_NO_RESPONSE_REMINDER`) |
