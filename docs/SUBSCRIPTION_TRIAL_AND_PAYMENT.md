# Подписка тренера: пробный период и оплата

## Тарифы и выбор плана

В системе есть **платные планы** подписки: Месяц, 3 месяца, Год, 1,5 года (см. таблицу `subscription_plans`, миграция 0045). Тренер **выбирает план** в Mini App «Оплатить подписку»: сначала видит карточки тарифов, по нажатию переходит к оплате выбранного срока.

Оплата всегда за **следующий период**: с даты окончания текущей подписки (или с сегодня, если подписки нет). В Mini App перед редиректом на платёж показывается текст вида: «Оплата подписки «Год» за период с … по … — X BYN».

## Тестирование оплаты подписки без реальных списаний

Оплата подписки идёт через bePaid. Чтобы тестировать **без списания денег**:

### Вариант 1: Stub (без ключей bePaid)

1. В `.env` **не задавайте** `BEPAID_SHOP_ID` и `BEPAID_SECRET_KEY` (или оставьте пустыми).
2. Убедитесь, что `PAYMENT_SANDBOX=true` (по умолчанию так).
3. Тренер в боте: команда **/subscription** или кнопка **«Оплатить подписку»** (в напоминании или в меню).
4. Откроется Mini App → запрос к API `subscription-payment-url` → редирект на «платёж». Без ключей адаптер вернёт **stub URL**: переход по нему сразу ведёт на страницу возврата с `payment_stub=1&tracking_id=inv_XXX`.
5. Страница `trainer-pay-subscription` вызовет **POST /api/webapp/trainer/subscription-stub-confirm** с этим `invoice_id` → подписка продлевается в БД (новая запись в `trainer_subscriptions`, invoice помечен paid).
6. Тренер видит экран «Подписка оплачена».

Итого: **никаких реальных платежей**, всё замыкается на stub и stub-confirm.

### Вариант 2: bePaid sandbox (реальный флоу с тестовыми картами)

Проверка полного цикла: форма bePaid → оплата тестовой картой → webhook → продление подписки в БД.

1. **Ключи bePaid**  
   Получите у bePaid (или в [кабинете merchant.bepaid.by](https://merchant.bepaid.by/)) `BEPAID_SHOP_ID` и `BEPAID_SECRET_KEY`. Отдельного sandbox-аккаунта нет — тест включается параметром `test: true` в запросе (у нас это `PAYMENT_SANDBOX=true`).

2. **`.env`** (пример для теста):
   ```env
   BEPAID_SHOP_ID=ваш_shop_id
   BEPAID_SECRET_KEY=ваш_secret_key
   BEPAID_CHECKOUT_BASE_URL=https://checkout.bepaid.by
   PAYMENT_SANDBOX=true
   API_BASE_URL=https://ваш-публичный-адрес   # см. п.4
   WEBAPP_BASE_URL=https://ваш-публичный-адрес
   ```

3. **Тестовые карты** (документация bePaid: [Test card data](https://docs.bepaid.by/en/integration/card_api/testing/)):
   - Успешная оплата (без 3-D Secure): **4200000000000000**
   - Неуспешная: **4005550000000019**  
   Срок действия и CVC — любые валидные (например 12/28, 111).

4. **Webhook**  
   bePaid вызывает **POST /api/webhooks/bepaid** после оплаты. URL строится как `{API_BASE_URL}/api/webhooks/bepaid`. Для локальной разработки нужен публичный HTTPS:
   - Запустите ngrok: `ngrok http 8000`
   - В `.env` укажите `API_BASE_URL=https://xxxx.ngrok.io` и `WEBAPP_BASE_URL=https://xxxx.ngrok.io`
   - В Telegram Mini App ссылки должны открываться по этому же HTTPS (Telegram требует HTTPS для Web App).

5. **Проверка**  
   Тренер в боте → «Оплатить подписку» → выбор тарифа в Mini App → переход на bePaid → оплата картой 4200000000000000 → возврат в Mini App; webhook подтверждает инвойс → подписка продлевается.

## Настройка пробного периода (trial)

- План «Пробный период» хранится в БД: таблица `subscription_plans`, запись с `is_trial = true` (сиды в миграции 0042: 14 дней).
- **Срок trial** задаётся полем `period_days` у этого плана.

### Способ 1: переменная окружения (без правки БД)

В `.env`:

```env
TRIAL_PERIOD_DAYS=7
```

Если задано, при создании пробной подписки используется это значение вместо `period_days` из плана в БД. Подходит для быстрой смены срока (7, 14, 30 дней) без миграций.

### Способ 2: правка в БД

```sql
UPDATE subscription_plans SET period_days = 14 WHERE is_trial = true;
```

Если **не** задан `TRIAL_PERIOD_DAYS`, используется именно это значение из БД.

## Напоминание «подписка скоро закончится»

- Раз в сутки фоновая задача проверяет подписки и:
  1. Переводит в **past_due** те, у которых `expires_at` уже в прошлом (доступ к каталогу и т.д. блокируется).
  2. Отправляет тренеру напоминание за **N дней** до `expires_at`.

Текст напоминания: *«Подписка заканчивается DD.MM.YYYY. Оплатите до этой даты (можно заранее) — иначе доступ к каталогу и записям будет приостановлен.»* + кнопка **«Оплатить подписку»**.

### За сколько дней напоминать

В `.env`:

```env
SUBSCRIPTION_REMINDER_DAYS_AHEAD=5
```

По умолчанию **3** дня. Напоминание уходит один раз на подписку (флаг `reminder_sent_at`).

## Кратко

| Что | Как |
|-----|-----|
| Тест оплаты без денег | Не задавать BEPAID_* → используется stub, после «оплаты» вызывается stub-confirm |
| Срок пробного периода | `TRIAL_PERIOD_DAYS` в .env или `period_days` у плана с `is_trial = true` в БД |
| За сколько дней предупреждать | `SUBSCRIPTION_REMINDER_DAYS_AHEAD` (по умолчанию 3) |
