# Сертификаты: безопасность и порядок списания

## 1. Длина и безопасность кода

- **Было:** 6 символов (A–Z, 0–9) → ~2.2 млрд комбинаций. При переборе или утечке списка коды можно подбирать.
- **Стало:** 10 символов → ~3.7·10¹⁵ комбинаций. Перебор нереалистичен; формат остаётся удобным (CERT-XXXXXXXXXX).

Рекомендации (sport tech / best practices):

- Код только для привязки к аккаунту; **списание — только на бэкенде** при «Проведено», не по вводу кода тренером.
- Не показывать полный код в публичных местах; в письме/PDF — нормально для получателя.
- При желании можно добавить **rate limit** на `POST /client/certificates/activate` (например, 5 попыток в минуту с одного IP/пользователя).
- Логировать неуспешные попытки активации по коду (подбор, опечатка).

## 2. Абонемент и сертификат одновременно

Сейчас порядок жёстко зафиксирован в коде:

1. При переводе бронирования в статус **completed** вызывается `redeem_pass_session_for_booking` — списание **одного занятия с абонемента** (если есть подходящий по тренеру/услуге).
2. Если абонемент **не списался** (нет подходящего или остаток 0), вызывается `redeem_certificate_balance_for_booking` — списание **суммы занятия с сертификата** этого тренера.

Итого: **сначала всегда абонемент, потом сертификат**. Это разумно: абонемент «привязан» к пакету занятий, сертификат — к денежному номиналу.

В перспективе (мерч и т.п.):

- Для **занятий** — порядок не менять.
- Для **других типов списания** (мерч, доп. услуги) — отдельные use case’ы, которые списывают только с сертификата (или только с «баллов») по своим правилам. Модель `amount_remaining_cents` это уже допускает.

## 3. Привязка сертификата к тренеру

Да, сертификат привязан к **конкретному тренеру**:

- В `certificate_instances` есть `trainer_id` (кто выдал).
- `redeem_certificate_balance_for_booking` списывает только с сертификатов, у которых `trainer_id = trainer_id` **этого бронирования** и `activated_client_id = client_id` клиента с бронированием.

Если клиент идёт на занятие **к другому тренеру**, у этого бронирования другой `trainer_id` → с сертификатов первого тренера ничего не списывается. Списывается только баланс сертификата **этого** тренера (если он есть у клиента).

## 4. Как клиент ходит по абонементу/сертификату и насколько это безопасно

Фактический поток:

1. Клиент записывается на занятие (в боте/приложении) к тренеру → создаётся **бронирование** (client_id, trainer_id, slot, service).
2. Тренер в боте/приложении видит брони и нажимает **«Проведено»** (или система переводит в completed по правилам).
3. **Бэкенд** при переходе в `completed`:
   - вызывает `redeem_pass_session_for_booking(booking_id)` — списание с абонемента **этого** клиента у **этого** тренера;
   - если не списалось — вызывает `redeem_certificate_balance_for_booking(booking_id)` — списание с сертификата **этого** клиента у **этого** тренера.

То есть списание делается **не** по тому, что клиент «показал» код или экран. Решение принимает **система** по факту проведённого занятия (бронирование + «Проведено»). Тренер лишь подтверждает проведение; он может при желании в интерфейсе видеть, что у клиента есть активный абонемент/сертификат по нему — для информирования, а не для ручного ввода кода.

Безопасность:

- Подделать «проведение» может только тот, у кого есть доступ к аккаунту **тренера** (отметить занятие проведённым). Риск — компрометация аккаунта тренера, а не подделка кода клиентом.
- Клиент не может «показать» чужой сертификат и списать его у другого тренера: списание только по `(client_id, trainer_id)` из бронирования.
- Клиент не может дважды списать одно занятие: списание идёт в одной транзакции с переводом бронирования в completed, повторный вызов для того же бронирования не должен повторно списывать (логика в `redeem_pass_session_for_booking` / `redeem_certificate_balance_for_booking` и в том, что бронирование уже completed).

Итого: **достаточно, чтобы тренер видел в боте активный сертификат/абонемент у клиента и нажимал «Проведено»** — списание выполняется на бэкенде корректно и привязано к тренеру и клиенту. Дополнительно «показывать» код тренеру не обязательно; код нужен только для **активации** сертификата в аккаунт клиента (один раз).

## 5. Что уже сделано в коде

- Код сертификата: **10 символов** (CERT-XXXXXXXXXX).
- Порядок при проведении: **сначала абонемент, потом сертификат**.
- Сертификат списывается **только у того тренера**, у которого проведено занятие (`trainer_id` бронирования).
- Списание — **только на бэкенде** при переходе бронирования в completed, не по вводу кода.

При необходимости дальше можно добавить: rate limit на активацию по коду, логирование неуспешных активаций, отдельные сценарии списания сертификата на мерч/другие цели.

## 6. Выдача сертификата: кто такой «клиент» и «получатель»

Сценарий:

- Тренер принимает оплату от **покупателя** (тот может быть или не быть клиентом в CRM). Покупатель называет: свои контакты, **email** (куда прислать PDF), **имя получателя** (кому подарок — указывается в сертификате).
- Тренер в боте/веб-приложении: выбирает номинал сертификата, вводит **имя получателя** (кому в подарок), email (для отправки PDF). Опционально может выбрать клиента из поиска (для подстановки телефона или будущей привязки в CRM); при этом **имя получателя не подставляется** из карточки клиента — его вводят вручную, т.к. получатель подарка часто другой человек.
- PDF и письмо содержат **имя получателя** (получатель подарка), а не имя «клиента» из CRM.
- После оплаты тренер нажимает «Выдать» → сертификат создаётся, PDF уходит на указанный email. Сделка закрыта. Покупатель передаёт сертификат (или пересылает письмо) получателю.

Получатель подарка:

- Открывает бота по ссылке с кодом (например `cert_XXXX`) или заходит в «Мои сертификаты» и вводит код.
- Активирует сертификат (привязка к своему аккаунту).
- После активации в ответе API возвращаются `city_id`, `service_id`, `trainer_id` (город и тренер из профиля тренера). Клиентское приложение вызывает `POST /client/session` с этими данными → в сессии выбираются **город и тренер** (владелец сертификата). При открытии каталога/вкладки тренера у пользователя уже выбран этот тренер и город — можно сразу записываться на занятие.
