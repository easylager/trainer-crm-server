# Запись клиента тренером: идентификация по телефону и «новый» клиент

## Проблема

Тренер хочет записать на слот человека, который:
- ещё не записан в системе (написал в Telegram, договорились устно);
- в базе его нет → нет `client_id`, нет `telegram_id`.

Сейчас клиент в БД жёстко привязан к `telegram_id` (уникальный, NOT NULL). Запись возможна только для тех, кто уже есть в `clients` (как правило, кто хотя бы раз записывался через бота).

## Идеи

### 1. Идентификация по телефону (основная)

- **Сделать `clients.telegram_id` nullable.**  
  Тогда возможны два типа записей:
  - «Обычный» клиент: есть `telegram_id` (заходил в бота) — уведомления в Telegram, история в боте.
  - «Клиент без бота»: `telegram_id = NULL`, обязательны хотя бы `phone` и имя (`first_name` или `last_name`). Создаётся тренером при ручной записи.

- **Уникальность:**  
  - По `telegram_id` — как сейчас (один аккаунт = один client).  
  - По телефону — либо один client на номер (unique на нормализованный phone), либо разрешаем дубликаты и при «привязке» Telegram потом склеиваем. Проще на первом этапе: **уникальный индекс по нормализованному телефону** (цифры только), один client на номер.

- **Поиск при записи:**  
  - Список «кого я уже тренировал» (как сейчас) + **поиск по телефону** (фильтр по введённым цифрам).  
  - Если тренер ввёл телефон и нашёлся один client — подставляем его.  
  - Если не нашёлся — кнопка **«Добавить нового»** → форма: имя, телефон → создаём client с `telegram_id = NULL`.

### 2. «Новый клиент» с экрана записи

- Тренер нажимает «Записать на слот» → видит список клиентов + поиск по телефону + кнопку **«Новый клиент»**.
- «Новый клиент»: поля **Имя** (или Имя + Фамилия), **Телефон**. Обязательно телефон (как идентификатор).
- В бэкенде: `get_or_create_client_by_phone(trainer_id?, phone, first_name, last_name)` → если client с таким телефоном есть (нормализованно) — возвращаем его и при необходимости обновляем имя; иначе создаём новую запись с `telegram_id = NULL`, `phone = ...`, `first_name`, `last_name`.
- Запись (booking) создаётся как обычно: `slot_id`, `trainer_id`, `client_id`, `created_by_trainer=True`.

### 3. Уведомления и напоминания

- Если у client есть `telegram_id` — всё как сейчас: напоминания и отмены в бота.
- Если `telegram_id = NULL` — push в Telegram не отправляем. Тренер сам звонит/пишет по телефону (или позже добавим SMS/другой канал). В карточке записи и в «Мои записи» показываем телефон и пометку «Без бота».

### 4. Привязка Telegram позже

- Когда человек впервые зайдёт в клиентского бота (по ссылке с сайта/каталога), можно:
  - спросить «Введите номер телефона» и по нему найти client с `telegram_id = NULL` и привязать: `UPDATE clients SET telegram_id = :tid WHERE id = :cid`;
  - или показать «Вас записал тренер X? Привязать запись к этому аккаунту?» (если по какой-то причине знаем, что это он).
- После привязки клиент получает все уведомления в боте и видит свои записи.

### 5. Альтернатива: «гостевой» визит без client_id

- Можно было бы сделать `bookings.client_id` nullable и хранить «гостя» как текст (имя + телефон в комментарии). Минусы: нет единой истории по человеку, дубликаты, сложнее отчёты. **Рекомендация:** не делать; один человек = один client (с телефоном и опционально telegram_id).

## План реализации (кратко)

1. **Миграция:** `clients.telegram_id` → nullable; уникальный индекс по нормализованному `phone` (или без уникального, если решим склеивать вручную).
2. **Приложение:**  
   - `get_or_create_client(telegram_id=None, phone=..., first_name=..., last_name=...)` — создание/поиск по телефону при отсутствии telegram_id.  
   - Для бота/каталога по-прежнему `get_or_create_client(telegram_id=user.id, ...)`.
3. **API для тренера:**  
   - Список клиентов тренера с поиском по телефону (query param `phone=` или `q=`).  
   - POST «создать клиента» (имя, телефон) → возврат `client_id` для последующей записи на слот.
4. **Mini App «Расписание»:** по клику на свободный слот — экран «Выберите клиента»: список + поиск по телефону + «Новый клиент» (форма имя + телефон) → создание client (если новый) и создание booking.

После этого тренер сможет записывать и тех, кого раньше тренировал (поиск по телефону/имени), и новых людей по имени и телефону без Telegram.
