## ВИЗИЯ ПРОДУКТА

Цель: из текущего ядра (боты + мини‑аппы + расписание + абонементы/сертификаты + уведомления) вырастить **#1 CRM/маркетплейс для тренеров в РБ**, который:

- для тренера = **CRM + автоматизация «рутины»** (график, клиенты, деньги, аналитика, коммуникации);
- для клиента = **маркетплейс** с лучшим UX записи и оплаты (быстрая запись, прозрачные цены, отзывы, абонементы);
- для платформы = масштабируемая архитектура (чистые слои, B2B‑фокус, готовность к мульти‑городам/странам и B2B‑интеграциям).


## ОСНОВНЫЕ ПРИНЦИПЫ (К ЧЕМУ ПРИМЕРЯЕМ ЛЮБОЙ ФИЧЕРЕКВЕСТ)

- **«Быстрее, чем договориться в чате»**: путь клиента от «хочу позаниматься» до подтверждённой записи должен быть короче и надёжнее, чем переписка в мессенджере.
- **«Тренер не открывает Excel»**: всё, что сейчас делают в таблицах/тетрадях (учёт занятий, оплат, абонементов, клиентов), должно быть естественно в системе.
- **«Не ломать голову про нал»**: тренер понимает, сколько он заработал, сколько должен заплатить платформе и налогам, и видит это в одном месте.
- **«Инфраструктура не тормозит»**: фото, слоты, опросы, списки должны работать как нативное приложение, даже в мини‑аппе Telegram.
- **Чистая архитектура**: доменная логика не зависит от транспорта (бот, WebApp, публичное API). Всё новое строим через use‑cases и адаптеры.


## ТЕКУЩЕЕ СОСТОЯНИЕ (БАЗА, НА КОТОРОЙ СТРОИМ)

Уже есть:

- Боты (клиентский и тренерский) + Mini App «каталог / запись / абонементы / сертификаты».
- Слоты, расписание, ближайшие окна (в т.ч. оптимизированная загрузка по тренеру).
- Абонементы и сертификаты, расчёт экономии на абонементе.
- Фото с S3/R2 + CDN, оптимизации загрузки, кэш, диагностические подписи.
- Заявки клиентов (общие и персональные), уведомления тренерам, ответы тренеров.
- Архитектура use‑cases (application), репозитории (infrastructure), API‑роуты, боты поверх.

Дальше строим **продуктовый план**, а не только технический.


## КАРТА ПРОДУКТА: ЧТО НУЖНО ДЛЯ «ТОП‑1 CRM/МАРКЕТПЛЕЙСА»

### 1. CRM ДЛЯ ТРЕНЕРА (ВНУТРЕННЯЯ СТОРОНА)

1.1. **Контакты и сегментация клиентов**
- Единая карточка клиента: контакты, история занятий, абонементов, заявок, комментарии тренера.
- Теги и сегменты (дети/взрослые, уровень, группа, травмы/ограничения).
- Быстрый поиск клиента по имени/телефону/никам.

1.2. **Расписание и группы**
- Гибкие шаблоны: индивидуалки, малые группы, большие группы.
- Привязка клиентов к слотам/группам, лист ожидания, ограничения по вместимости.
- Автогенерация слотов на месяц вперёд; массовые изменения (каникулы, переносы).

1.3. **Учёт посещаемости и абонементов**
- Отметка «пришёл / не пришёл / отменил поздно» из тренерского бота в 1–2 клика.
- Списание занятий с абонемента, остаток по абонементу, история списаний.
- Отчёт по клиенту: сколько занятий купил, сколько посетил, пропуски.

1.4. **Финансы тренера**
- Дашборд: выручка по периодам, по услугам, по клиентам.
- Учёт налички vs онлайн‑платежей (через платформу).
- План/факт по абонементам и разовым занятиям, задолженности (если тренер пускает «в долг»).


### 2. МАРКЕТПЛЕЙС ДЛЯ КЛИЕНТА

2.1. **Поиск и выбор тренера**
- Улучшенный каталог: фильтры по уровню, возрасту, типу тренировок, времени, цене.
- SEO внутри Telegram: короткие описания, фото, значки «Хит», «Новичок».
- Отзывы и рейтинги (после завершённого занятия).

2.2. **Запись и оплата**
- Чёткий сценарий: выбрал тренера → выбрал слот → оплатил → получил подтверждение.
- Поддержка абонементов/сертификатов: покупка, привязка к клиенту, списание при записи.
- Разные способы оплаты (карта, Apple/Google Pay, позже — счёт/ЕРИП), stub/sandbox для разработки.

2.3. **Коммуникации**
- Безопасный канал «клиент ↔ тренер» через бота (месседжи привязаны к брони/клиенту).
- Шаблоны сообщений от тренера (напоминания, домашка, поздравления).


### 3. МОЗГИ ПЛАТФОРМЫ (АНАЛИТИКА, АВТОМАТИЗАЦИЯ)

3.1. **Аналитика по тренеру и по площадке**
- LTV клиентов, удержание, возвращаемость, воронки (заявка → запись → регулярные занятия).
- Сравнение периодов: прошлый месяц / текущий, лучшие дни/часы.

3.2. **Автоматические триггеры**
- Напоминания о тренировке, об окончании абонемента, о незакрытых заявках.
- Реактивация «уснувших» клиентов (скрипты в боте, специальные предложения).

3.3. **Анти‑no‑show и политика отмен**
- Правила отмены (за N часов) и штрафы (списание занятия, платная отмена).
- Чёткая логика в коде + прозрачный UX для клиента.


### 4. B2B-СТОРОНА (НАЧИНАЕМ С ПРОСТОГО)

4.1. **Подписка тренера**
- Уже есть: планы, инвойсы, интеграция с BePaid (stub + готовность к бою).
- Доделать: более явный «центр подписки» в тренерском боте / Mini App (история счетов, статусы).

4.2. **Маркетинговые инструменты для тренера**
- Промокоды, акции, партнёрские ссылки (можно отложить, но заложить в архитектуру).


## ПОШАГОВЫЙ ПЛАН РАЗВИТИЯ ИЗ ТОГО, ЧТО ЕСТЬ

### Этап 1. Довести ядро записи и заявок до «идеала»

1. Починить/отполировать все крайние кейсы записи через Mini App и бота (персональные заявки, слоты, время ответа).
2. Завести **единый документ UX‑флоу**: «как клиент попадает в запись» (бот, мини‑апп, заявка) и привести код к этому флоу.
3. Завести расширенную **карточку клиента**: начать хранить историю заявок и записей так, чтобы её можно было показать тренеру.

Результат: запись через систему реально удобнее, чем «написать в личку».


### Этап 2. Мини‑CRM для тренера

1. Добавить в Mini App тренера раздел **«Клиенты»**:
   - список клиентов с базовой статистикой (посещений, абонементов, заявок);
   - карточка клиента с историей и заметками.
2. Вынести **учёт абонементов и посещаемости** в отдельный блок в карточке тренера и клиента.
3. Ввести простые **отчёты по выручке** (месяц/неделя, по услугам).

Результат: тренер может вести весь учёт в системе, не открывая Excel.


### Этап 3. Монетизация и платёжная инфраструктура

1. Довести до конца **подписку тренера**:
   - полноценный боевой путь через BePaid sandbox → прод;
   - прозрачные статусы подписки в боте и Mini App.
2. Спроектировать и реализовать **оплату клиентами** (за занятия/абонементы):
   - доменная модель «покупка» (purchase) и «право на занятие» (entitlement);
   - интеграция с BePaid через уже существующий `PaymentGateway`.
3. Минимальный **раздел «Финансы» для тренера** (сколько пришло через платформу).


### Этап 4. Усиление маркетплейса

1. Добавить **отзывы и рейтинги**, завязанные на завершённые брони.
2. Улучшить каталог: дополнительные фильтры, сортировки, подсветка «сильных» тренеров.
3. Запустить простую **рекомендательную логику** (похожие тренеры, популярные в городе/арене).


### Этап 5. Глубокая аналитика и автоматизация

1. Вынести ключевые метрики по тренеру и по площадке в отдельный модуль (application/use_cases + API).
2. Автоматизировать триггеры (reactivation, напоминания, no‑show‑политика) на базе уже существующих notification‑loops.
3. Подготовить публичное API для интеграций (B2B‑клиенты: школы, аренды, партнёры).


## ТЕХНИЧЕСКИЕ ПРИНЦИПЫ ДЛЯ ДАЛЬНЕЙШЕЙ РАБОТЫ

- **Чистые слои уже есть — продолжаем их соблюдать**: доменная логика (use_cases) не должна знать про Telegram/WebApp/BePaid.
- **Всё, что касается денег и подписок — только через отдельный модуль billing** (уже начат с `payment_gateway` и subscription_use_cases).
- **Все новые фичи документируем в `docs/`**: отдельный план/ADR на крупную фичу (CRM клиентов, оплаты клиентов, аналитика, подписки).

Этот документ — верхнеуровневая карта. Дальше можно брать по этапу (например, «Этап 2. Мини‑CRM для тренера») и расписывать детальный технический план в отдельном файле `docs/…`, чтобы шаг за шагом приближаться к системе, которая обгонит uclients по удобству для тренера и клиента.
