## 1. Как в отчёте читать клинья и рычаги

- **Клин 1** — тренер в TG: записал → напоминание → пометка, без «качай CRM».
- **Клин 2** — ссылка клиенту, сам записался.
- **Клин 3** — вертикаль ice / комьюнити, не обезличенный SaaS.
- **Клин 4** — новый клиент пришёл сам → CRM как канал привлечения, retention.

**Рычаги:** запись · ссылка·привлечение · retention · монетизация (см. промпт).

## 2. Этапы активации (как их вижу в продукте сейчас)

### Тренер

1. **Привязка по ссылке** (`link_<token>`) → гейт до `active` (см. `docs/TRAINER_BOT_ONLY_ONBOARDING_CHECKLIST.md`).
2. **Анкета / модерация** → статус `active` (до этого слоты и «рабочие» сценарии закрыты — сообщение про активацию).
3. **Хаб Mini App** — блок **«Первые шаги»** (`GET /trainer/onboarding/checklist`): профиль → слоты в горизонте → шаг про первую запись (флаг `has_any_booking` / подтверждённая бронь — см. `trainer_onboarding_checklist.py` + `trainer-home-main.js`).
4. **Первая подтверждённая бронь** → `try_claim_first_booking_milestones` при **создании записи тренером** и при **подтверждении** клиентской записи (`booking_use_cases.py`) → в боте поздравление + **тип «поделись каталогом/ссылкой»** (`trainer_handlers.py` + `build_trainer_invite_links`).

### Клиент

1. **`/start`** → меню + «Тренеры и запись» / золотой путь в `docs/CLIENT_GOLDEN_PATH_ACCEPTANCE.md`.
2. **Каталог** → карточка → запись в `book` (или заявка B).
3. **Альтернатива клину 2/4** — deep link / welcome: сессия + URL `service_id`, слоты согласованы с услугой (недавние правки API + `book.html` + бот).

**Связь с MVP:** метрики «дней до первой подтверждённой брони ≤ 21» и «≥60% с бронью» (`docs/MVP_SUCCESS_CRITERIA.md`) напрямую завязаны на плавность этапов 1–4 у тренера и на ликвидность клиентского пути.

## 4. Сильные стороны (зафиксировать как «не сломать»)

- **Склейка клинов 2 и 4:** сессия клиента + query `service_id` + fallback в `GET /client/slots` при совпадении тренера — снижает риск «пустых групповых» после ссылки.
- **Двойной триггер milestone:** и тренерская запись, и подтверждение inbound-клиента — выравнивает мотивацию «дам ссылку» с реальным первым успехом.
- **Золотой путь клиента** в доке — хорошая основа для QA; нужно лишь синхронизировать с текущим UI успеха (PR-01).

## 5. Вопросы к бизнесу

1. **Модерация до `active`:** осознанный барьер доверия — есть ли целевой SLA (часы/дни), который можно обещать тренеру в продукте?
2. **Комиссия / marketplace в будущем:** когда клин 4 станет метрикой роста, нужна ли явная политика прозрачности для тренера («кто платит за лида»)?
3. **Ice-first:** готовы ли выделить **1–2 экрана** в пилоте под узнаваемый ice-copy (не весь продукт), чтобы закрепить клин 3 в онбординге?

## 6. Aha / vertical gaps (клин 3)

| Наблюдение | Комментарий |
|--------------|-------------|
| Каталог и запись | Тексты в целом **универсальные** («тренер», «услуга», «арена») — ок для масштаба, но **редко цепляют** ice-комьюнити без точечных примеров (группа на льду, массовое катание и т.д.). |
| Хаб тренера | Блок «Первые шаги» функционален, но визуально **SaaS-onboarding**; точка «мы из ледового мира» пока в основном **вне продукта** (комьюнити, фидбек). |

Рекомендация: не раздувать scope — **один** персонализированный блок (копирайт + один пример сценария) на этапе после активации.

## 7. Рекомендованный порядок следующих шагов

1. Закрыть **PR-01** (док + приёмка под актуальный `book.html`).
