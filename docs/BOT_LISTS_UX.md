# Списки в Telegram-ботах: почему неудобно и как делать лучше

Ты прав: длинный текст + куча кнопок внизу, где по индексу надо угадать «кнопка 3 = строка 3» — это слабый UX. Ниже — почему так выходит, как это решают сильные боты и что можно сделать у нас без выноса всего на сайт.

---

## 1. В чём ограничение Telegram

- Нет «таблицы» или списка, где у каждой строки свои кнопки в одной карточке.
- Inline-кнопки идут **одним блоком под сообщением**. Текст — отдельно. Связь «строка N ↔ кнопка N» пользователь держит в голове.
- Чем длиннее список и чем больше кнопок — тем выше когнитивная нагрузка и риск нажать не то.

Поэтому «большой список текста + куча кнопок» в принципе не бывает «супер крутым» в классическом боте — это потолок формата.

---

## 2. Как это решают эталонные боты (подписки, коммерция)

Часто так:

- **Тяжёлые списки не живут в боте.** «Мои подписки», «История заказов», «Расписание на месяц» открываются в **Mini App (Web App)** — там нормальный список, карточки, фильтры. Бот остаётся для: уведомлений, быстрых действий (оплатить, продлить) и точки входа «Открыть в приложении».
- **Если список остаётся в боте** — его делают **коротким и однозначным**:
  - либо **список = кнопки**: каждая кнопка = один элемент (например «15.03 10:00 — Иванов»); нажал → открылось второе сообщение с деталями и действиями (Написать, Отменить). Нет «текст + отдельные кнопки по индексу»;
  - либо **мало элементов на экран** (3–5) + жёсткое правило «порядок кнопок = порядок строк» + пагинация «Далее».

То есть ответ на «как реально крутые боты это решают»: либо **не держат такие списки в боте** (Mini App / сайт), либо делают **список = кнопки** и «тап по элементу → экран с действиями», без длинного текста и индексов.

---

## 3. Паттерны, которые можно применить у нас

### 3.1 Список = кнопки (tap-to-expand)

Вместо «текст: 1. … 2. … 3. …» и внизу три кнопки «Действие 1 / Действие 2 / Действие 3»:

- **Одна кнопка = один элемент списка.** Подпись короткая: дата+время или «Заявка №3, Минск, теннис».
- Нажал кнопку → бот **редактирует сообщение** (или шлёт новое) с **одним** элементом: полное описание + кнопки действий только для него (Написать, Отменить, К списку).

Плюсы: нет сопоставления по индексу, действие привязано к конкретному элементу. Минус: при 20+ элементах — много кнопок и длинный скролл; нужна **пагинация** (например по 5–7 элементов на экран, кнопки «◀ Назад» / «Вперёд ▶»).

### 3.2 Короткие страницы + жёсткий порядок

Если оставляем формат «текст + кнопки под ним»:

- Показывать **не больше 5 элементов** на одном сообщении.
- Ровно **5 кнопок** (или меньше, если элементов меньше), в **том же порядке**, что и строки. Подписи кнопкам давать **осмысленные** (например «15.03 10:00» или «Заявка Минск, теннис»), а не «1», «2», «3».
- Внизу: «Страница 1 из 3» и кнопки пагинации.

Так «кнопка = строка» хотя бы визуально и по смыслу легче угадывается.

### 3.3 Одно сообщение на элемент (редко)

Для «Мои записи» можно было бы: каждая запись = отдельное сообщение с одной строкой кнопок под ней (Написать, Отменить). Тогда связь «кнопка–элемент» идеальная, но при 10 записях — 10 сообщений, чат раздувается. Имеет смысл только при малом числе элементов (2–5).

### 3.4 Тяжёлые списки — в Mini App или на сайт

«Моё расписание» (календарь, много слотов), длинный «Мои записи» с фильтрами, «Мои заявки» с историей — это то, что в сильных ботах чаще выносят в **Web App (Mini App)** или на **сайт**. В боте остаётся: уведомление + кнопка «Открыть расписание» / «Мои записи» → открывается Mini App или браузер. Так списки становятся «реально классными» за счёт нормального UI, а не за счёт костылей в чате.

## 4. Что конкретно делать с нашими экранами

| Экран | Сейчас | Что сделать в первую очередь |
|-------|--------|-------------------------------|
| **Мои записи (тренер)** | Текст по дням + внизу «Написать» / «Отменить» → выбор записи по списку | **Список = кнопки:** одна кнопка на запись (коротко: «15.03 10:00 Иванов»). Тап → второе сообщение с этой записью и кнопками [Написать] [Отменить]. Если записей > 7 — пагинация. |
| **Мои записи (клиент)** | Текст списка + кнопка «Назад» (отмена/написать — через тренера по ссылке) | Либо так же «список = кнопки» (тап → детали записи + при необходимости подсказка «написать тренеру» по ссылке). Либо оставить как есть, но список коротким (только активные) и не длинным. |
| **Мои заявки (клиент)** | Текст заявок + кнопки по индексу | **Список = кнопки:** «Заявка Минск, теннис» → тап → одна заявка + отклики и действия. Пагинация при большом числе. |
| **Заявки клиентов (тренер)** | Список заявок + кнопки «Откликнуться» по индексу | Аналогично: кнопка = заявка, тап → одна заявка + кнопка «Откликнуться» / «Назад к списку». |
| **Моё расписание (тренер)** | Текст по неделям/дням + много кнопок | Самый тяжёлый вариант. Лучший UX — **Mini App** или **страница на сайте** с календарём. В боте минимум: «Эта неделя» (короткий список слотов) + одна кнопка **«Открыть расписание на сайте»** (или в Mini App). |

---

## 5. Итог

- Твоё беспокойство обосновано: **«большой текст + куча кнопок по индексу» в Telegram по определению не бывает супер-крутым.** Так устроена платформа.
- **Эталонные боты** либо **не держат такие списки в чате** (Mini App / сайт), либо делают **список = кнопки** с переходом «тап по элементу → один элемент + действия».
- **Что сделать у нас:** для «Мои записи», «Мои заявки», «Заявки клиентов» перейти на паттерн **«список = кнопки» + тап → детали и действия** и при необходимости добавить пагинацию. Для «Моё расписание» честно считать лучшим решением **вынос в Web App или на сайт**, а в боте оставить краткий обзор + кнопку «Открыть на сайте».

Так списки перестают быть «текст + индексы» и становятся максимально удобными в рамках того, что Telegram вообще умеет.
