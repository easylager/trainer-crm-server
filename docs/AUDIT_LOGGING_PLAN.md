# План аудит-логирования (3.2.3)

Цель: фиксировать значимые действия пользователей и системы для разбора инцидентов, модерации и аналитики. Логируем **кто**, **что**, **когда**, **источник** (API / бот), **результат** (успех/ошибка) и минимальный контекст (id сущностей, без PII в логах по умолчанию).

---

## 1. Что логировать

### 1.1 Тренеры (модерация и профиль)

| Действие | Где | Кто (actor) | Контекст |
|----------|-----|-------------|----------|
| Создание тренера | API `POST /api/trainers` | — (нет auth, с сайта) | `trainer_id` |
| Обновление профиля тренера | API `PATCH /api/trainers/{id}/profile` | — | `trainer_id`, поля (без сырых текстов при желании) |
| Смена статуса тренера | API `PATCH /api/trainers/{id}/status` | — | `trainer_id`, `old_status`, `new_status` |
| Одобрение тренера (модерация) | Админ-бот | `admin_telegram_id` | `trainer_id` |
| Отклонение тренера | Админ-бот | `admin_telegram_id` | `trainer_id` |
| «Нужны правки» + фидбек | Админ-бот | `admin_telegram_id` | `trainer_id` |
| Привязка Telegram к тренеру (по ссылке) | Тренерский бот | `telegram_id` | `trainer_id` (после резолва) |

### 1.2 Записи (bookings)

| Действие | Где | Кто | Контекст |
|----------|-----|-----|----------|
| Создание записи | Клиентский бот | `client_telegram_id` | `booking_id`, `trainer_id`, `slot_id` (без телефона/коммента в лог при желании) |
| Отмена записи тренером | Тренерский бот | `trainer_telegram_id` | `booking_id`, `trainer_id` |
| Отметка «Занятие прошло» (completed) | Тренерский бот | `trainer_telegram_id` | `booking_id` |

### 1.3 Заявки клиентов (client_requests) и отклики

| Действие | Где | Кто | Контекст |
|----------|-----|-----|----------|
| Создание заявки (город, услуга, комментарий) | Клиентский бот | `client_telegram_id` | `request_id`, `city_id`, `service_id` |
| Отклик тренера на заявку | Тренерский бот | `trainer_telegram_id` | `request_id`, `trainer_id`, `response_id` |

### 1.4 Расписание тренера (слоты и шаблоны)

| Действие | Где | Кто | Контекст |
|----------|-----|-----|----------|
| Добавление шаблона (день, часы) | Тренерский бот | `trainer_telegram_id` | `trainer_id`, `day_of_week`, кол-во часов |
| Удаление шаблона | Тренерский бот | `trainer_telegram_id` | `trainer_id`, `template_id` |
| Применение расписания на неделю | Тренерский бот | `trainer_telegram_id` | `trainer_id`, `week_start`, кол-во слотов |
| Удаление слота (available) | Тренерский бот | `trainer_telegram_id` | `trainer_id`, `slot_id` |

### 1.5 Оценки и отзывы

| Действие | Где | Кто | Контекст |
|----------|-----|-----|----------|
| Оценка тренера 1–5 + опциональный отзыв | Клиентский бот | `client_telegram_id` | `trainer_id`, `booking_id`, `rating` (без текста отзыва в лог при желании) |
| Отзыв тренера о занятии | Тренерский бот | `trainer_telegram_id` | `booking_id`, `trainer_id` |

### 1.6 API (опционально, общий слой)

- Важные мутирующие эндпоинты: `POST /api/trainers`, `PATCH .../profile`, `PATCH .../status`, загрузка фото. Либо логировать в роутах, либо один middleware по методу + path (без тела запроса в лог).

---

## 2. Формат и хранение

- **Структурированный лог (JSON)** в stdout: один объект на событие. Поля: `ts` (ISO), `event`, `actor_type` (client_bot | trainer_bot | admin_bot | api), `actor_id` (telegram_id или «api»), `payload` (dict с id и т.д.). Так удобно собирать в Loki/CloudWatch/ELK.
- **Опционально — таблица `audit_events`** в БД: те же поля + персистентность для отчётов и поиска по `trainer_id`/`booking_id`. Реализовать можно во второй итерации после вывода в лог.

Рекомендация: начать с **только лог** (единый хелпер `audit_log(event, actor_type, actor_id, payload)`), потом при необходимости добавить запись в БД из того же хелпера.
