# План API для сайта в связке с ботами

Детальный план расширения API: что уже есть, что добавить для сайта, как делить доступ и как сайт взаимодействует с ботами.

---

## 1. Текущее состояние API

### 1.1 Роутеры и эндпоинты

| Роутер | Префикс | Назначение | Аутентификация |
|--------|---------|------------|----------------|
| **public** | `/api/public` | Каталог для клиентов и бота | Нет |
| **trainers** | `/api/trainers` | CRUD тренеров (создание, профиль, статус) | Нет (ожидается вызов с сайта/внутренний) |
| **upload** | `/api` | Загрузка фото тренера, presign | Нет |

### 1.2 Что уже умеет публичное API

- `GET /api/public/cities` — список городов
- `GET /api/public/services` — список услуг
- `GET /api/public/arenas?city_id=` — арены по городу
- `GET /api/public/trainers?limit=&offset=&city_id=&service_id=&arena_id=&order_by=` — активные тренеры с рейтингом, пагинация
- `GET /api/public/photos/{file_key}` — отдача фото из S3 (для бота и сайта)

### 1.3 Что уже умеет API тренеров (для сайта/бэкенда)

- `POST /api/trainers` — создать тренера (профиль, услуги, арены)
- `GET /api/trainers` — список тренеров (опционально `?status=active`)
- `GET /api/trainers/{id}` — тренер с профилем, фото, service_ids
- `PATCH /api/trainers/{id}/profile` — обновить профиль/услуги/арены
- `PATCH /api/trainers/{id}/status` — сменить статус (active, deactivated, …)
- `POST /api/upload/photo`, presign — загрузка фото

### 1.4 Чего нет в API, но есть в use cases (используют только боты)

- Слоты: `list_slots`, `get_slot`, создание/удаление слотов, шаблоны
- Записи: `create_booking`, `list_bookings_for_client`, `list_bookings_for_trainer`, `cancel_booking`
- Заявки клиентов: создание, список, отклики
- Токены привязки тренера: создание токена (сейчас только скрипт `create_trainer_link.py`), потребление — в боте по `link_<token>`
- Сессия клиента (город/услуга/тренер) — только в боте
- Deep link: формат описан в `docs/CLIENT_DEEP_LINK.md`; генерация ссылки сейчас на стороне сайта по конвенции

## 2. Роли и кто что вызывает

| Роль | Откуда вызывает | Нужно из API |
|------|------------------|--------------|
| **Публичная страница (каталог)** | Сайт (фронт) | Каталог, тренеры, фото. Опционально: свободные слоты тренера для отображения на странице тренера. |
| **Клиент** | Только бот | Запись, мои записи, заявки — в боте. Сайт только даёт ссылку в бота (deep link). |
| **Тренер (ЛК на сайте)** | Сайт (фронт) после входа | Профиль (чтение/редактирование), расписание (слоты: список, создание, удаление), возможно шаблоны. Вход: по логину/паролю или «магическая ссылка» (см. ниже). |
| **Бэкенд сайта (оплата, онбординг)** | Сервер сайта | Создать тренера, выдать ссылку на бота (создать trainer_link_token), при необходимости список тренеров. |
| **Админ (веб)** | Сайт (админка) | Справочники, статистика, «заморозить» тренера — при появлении веб-админки. Пока админ в боте. |

## 3. Аутентификация API

### 3.1 Сейчас

- Все эндпоинты без проверки пользователя. Вызовы с сайта предполагаются «доверенными» (один бэкенд).

### 3.2 Предлагаемая схема по зонам

| Зона | Метод | Назначение |
|------|--------|------------|
| **Публичная** (`/api/public/*`) | Без auth | Каталог, фото. Можно оставить так; при желании — rate limit по IP. |
| **Сайт-бэкенд** (создание тренера, выдача ссылки) | API Key в заголовке (например `X-API-Key`) или внутренняя сеть | Только сервер сайта знает ключ; боты ключ не используют. |
| **ЛК тренера** (профиль, слоты от имени тренера) | JWT или сессия после входа | Тренер логинится на сайте (логин/пароль или magic link); сайт выдаёт токен и подставляет в запросы к API. API проверяет токен и `trainer_id`. |

Вариант без отдельного «логина тренера на сайте» на старте: ЛК тренера доступен только по ссылке с одноразовым токеном (как сейчас бот `link_<token>`). Сайт генерирует тот же токен и может показать страницу «привяжи Telegram» + форму профиля/расписания; тогда часть операций «от имени тренера» можно делать по одноразовому токену в query/header до привязки Telegram. Детали — в фазе реализации ЛК.

### 3.3 CORS

- Для публичного каталога и (позже) ЛК тренера фронт будет слать запросы с домена сайта. Нужно настроить CORS в FastAPI: разрешить origin сайта, нужные методы и заголовки.

## 4. Эндпоинты: что добавить и как

### 4.1 Публичное API (каталог + интеграция с ботом)

- Уже есть всё необходимое для страниц «Города», «Услуги», «Тренеры», «Карточка тренера» и фото.
- **Добавить (опционально):**
  - `GET /api/public/trainers/{trainer_id}/slots?from_date=&to_date=` — свободные слоты (`status=available`) в диапазоне дат. Нужно для отображения на странице тренера «Когда свободен» без записи (сама запись — в боте по deep link). Ответ: список `{ id, slot_date, start_time, end_time }`.
- **Ссылка в бота с сайта:** единый формат уже описан в `docs/CLIENT_DEEP_LINK.md`. Имеет смысл добавить хелпер-эндпоинт без auth:
  - `GET /api/public/deep-link/client?city_id=&service_id=&trainer_id=` → ответ `{ "url": "https://t.me/CLIENT_BOT?start=client_1_2_5" }`. Имя бота брать из конфига (новая настройка `CLIENT_BOT_USERNAME` или из существующего места, если уже есть).

### 4.2 Бэкенд сайта: тренер + ссылка на бота

- **Создание тренера:** уже есть `POST /api/trainers`. Сайт после регистрации/оплаты вызывает его (желательно с сервера сайта с API Key).
- **Выдача ссылки на тренерского бота:**
  - Сейчас: скрипт `create_trainer_link.py` создаёт запись в `trainer_link_tokens` и печатает ссылку. Для сайта нужен аналог в API.
  - **Добавить:** `POST /api/trainers/{trainer_id}/link-token` (защитить API Key). Тело: `{ "expires_days": 7 }`. Ответ: `{ "token": "link_<value>", "bot_link": "https://t.me/TRAINER_BOT?start=link_..." }`. Внутри: сгенерировать `token`, вставить в `trainer_link_tokens`, сформировать `bot_link` из конфига (`TRAINER_BOT_USERNAME` или аналог).

### 4.3 ЛК тренера (профиль и расписание на сайте)

Зависит от того, как тренер «входит» на сайт (логин/пароль, magic link, одноразовый токен из письма). Ниже — минимальный набор эндпоинтов; auth-слой (JWT/сессия) добавляется при реализации входа.

- **Профиль**
  - Чтение: уже есть `GET /api/trainers/{id}`. Для ЛК тренера нужна проверка: запрос «от своего аккаунта» (текущий пользователь = этот trainer_id).
  - Редактирование: уже есть `PATCH /api/trainers/{id}/profile`. Аналогично — только для владельца.
  - Фото: уже есть upload/presign; в ЛК — те же эндпоинты с проверкой trainer_id.

- **Слоты (расписание)**
  - `GET /api/trainers/me/slots?from_date=&to_date=` — слоты текущего тренера (по JWT/session). Либо `GET /api/trainers/{id}/slots?...` с проверкой «текущий пользователь = id».
  - `POST /api/trainers/me/slots` — создать слот(ы). Тело: одна дата+время или массив (например на неделю). Использовать существующие use cases: `add_slot` / логику из `replace_slots_for_day`, `replace_week_with_template`.
  - `DELETE /api/trainers/me/slots/{slot_id}` — удалить слот (только `available`). Use case `delete_slot`.
  - Шаблоны (если ЛК будет их редактировать): отдельные эндпоинты для списка шаблонов и применения к неделе — позже, фаза 2.

### 4.4 Админ (веб)

При появлении веб-админки: справочники (города, арены, услуги) — CRUD через API; статистика — расширенный вариант того, что уже есть для админ-бота. Отдельный документ/фаза.

## 5. Контракт с ботами (что не меняем)

- **Клиентский бот** продолжает работать как сейчас: каталог и фото через `api_base_url` + `/api/public/*`; запись, мои записи, заявки — своей логикой и БД. Сайт только подставляет в deep link `client_<city_id>_<service_id>_<trainer_id>` и даёт ссылку на бота.
- **Тренерский бот** использует `link_<token>` из таблицы `trainer_link_tokens`; потребление токена — только в боте. Сайт/API только создаёт токен и возвращает ссылку.
- **Данные:** одна БД. Сайт и боты читают/пишут одних и тех же тренеров, слотов, записей. Изменения расписания в ЛК на сайте сразу видны боту и наоборот не требуются (бот не меняет расписание через API, только через свои хендлеры и use cases).

## 6. Конфиг и переменные для сайта

- Уже есть: `api_base_url`, `photo_base_url` (для бота и фронта).
- Добавить для генерации ссылок (в конфиге или env):
  - `client_bot_username` — без `@`, для deep link клиента.
  - `trainer_bot_username` — для ссылки «привязать Telegram» после оплаты.

## 7. Фазы реализации

### Фаза 1: Каталог + deep link + ссылка для тренера (минимум для сайта)

1. **Публичное API**
   - Оставить как есть: cities, services, arenas, trainers, photos.
   - Добавить `GET /api/public/deep-link/client?city_id=&service_id=&trainer_id=` → `{ "url": "https://t.me/...?start=client_..." }`.
   - Опционально: `GET /api/public/trainers/{id}/slots?from_date=&to_date=` — только доступные слоты (для отображения на странице тренера).

2. **Токен привязки тренера**
   - Добавить `POST /api/trainers/{trainer_id}/link-token` (с проверкой API Key). Ответ: токен и полная ссылка на тренерского бота.
   - В конфиг: `trainer_bot_username`, `client_bot_username`.

3. **CORS**  
   Настроить для домена сайта (и при необходимости для локального фронта).

4. **Документация**  
   Обновить README/OpenAPI: описание новых эндпоинтов и формата deep link.

### Фаза 2: ЛК тренера (профиль + расписание)

1. **Аутентификация тренера на сайте**  
   Выбрать схему: JWT после логина или одноразовый токен из письма/страницы. Реализовать выдачу и проверку токена (middleware/dependency в FastAPI).

2. **Эндпоинты «от имени тренера»**
   - `GET/PATCH /api/trainers/me` (или `/api/trainers/me/profile`) — профиль текущего тренера.
   - `GET /api/trainers/me/slots?from_date=&to_date=`
   - `POST /api/trainers/me/slots` — создание слотов (одно или несколько).
   - `DELETE /api/trainers/me/slots/{slot_id}`

3. **Фото**  
   Использовать существующие upload-эндпоинты с проверкой `trainer_id == current_user`.

### Фаза 3: Защита и админка

1. **API Key** для вызовов с бэкенда сайта (создание тренера, создание link-token). Проверка в FastAPI dependency.
2. **Rate limit** для публичных эндпоинтов (по IP или по заголовку).
3. **Веб-админка** (при необходимости): отдельный план эндпоинтов для справочников и отчётов.

## 8. Краткий чеклист по эндпоинтам

| Эндпоинт | Метод | Auth | Назначение |
|----------|--------|------|------------|
| `/api/public/*` (каталог, фото) | GET | — | Уже есть |
| `/api/public/deep-link/client` | GET | — | Ссылка в клиентского бота с prefill |
| `/api/public/trainers/{id}/slots` | GET | — | Свободные слоты (опционально) |
| `/api/trainers` (create, list, get, patch) | POST, GET, PATCH | API Key (для create) | Уже есть |
| `/api/trainers/{id}/link-token` | POST | API Key | Создать токен привязки + ссылка на бота |
| `/api/trainers/me`, `/api/trainers/me/slots` | GET, POST, DELETE | JWT/session тренера | Фаза 2 |

Такой план позволяет поэтапно ввести API для сайта без ломки ботов и с чётким разделением: каталог и ссылки в бота — сразу; ЛК тренера и админка — следующими шагами.
