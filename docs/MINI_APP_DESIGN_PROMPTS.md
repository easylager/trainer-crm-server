# Промты для унификации мини-приложений под `schedule.html`

Единая визуальная база:

1. **`static/webapp/theme.css`** — токены `--tg-theme-*` / `--app-*`.
2. **`static/webapp/mini-app-components.css`** — общие классы, вынесенные из эталона (shell body, `.bd-hero`, `.bd-btn`, `.filter-btn`, `.slot-card`, модалки, экраны `[data-screen]` и т.д.). **Не копировать эти блоки обратно в inline `<style>`** — расширять только сам `mini-app-components.css`, если паттерн нужен на нескольких страницах.
3. **`static/webapp/schedule.html`** — эталон композиции и поведения; страница подключает `theme.css` → `mini-app-components.css`.

### Строгая палитра: никаких «левых» цветов

- **Не вводить** произвольные `#hex`, `rgb`/`hsla`, именованные цвета (`blue`, `teal` и т.п.) для фона, текста, обводок, теней, заливок иконок и декоративных элементов.
- **Разрешено только:** `var(--tg-theme-*)`, `var(--app-*)` из `theme.css` и те же приёмы, что уже закреплены в эталоне **`schedule.html`** / **`mini-app-components.css`** (например янтарные `rgba(247, 166, 0, …)` для hero/акцента, семантика успеха/ошибки как у `.slot-status`, `.bd-btn--*`, `currentColor` там, где цвет наследуется от текста по токенам).
- Смысловые состояния (успех, опасность, нейтраль) — **не выдумывать новые оттенки**: брать `--app-success`, `--app-danger` и повторяемые из эталона комбинации, либо выразить через существующие токены и прозрачность.

## База: что взять из расписания

### Токены и фон (`theme.css`)

| Роль | Светлая тема | Тёмная тема |
|------|----------------|-------------|
| Фон | `--tg-theme-bg-color` (`#fffbec`) | `#000000` |
| Поверхности / карточки | `--tg-theme-secondary-bg-color` (`#fff5e1`) | `#1c1c1e` |
| Текст | `--tg-theme-text-color` | `#ffffff` |
| Подсказки | `--tg-theme-hint-color` | `#8e8e93` |
| Акцент кнопок | `--tg-theme-button-color` (`#f5a623`) | то же |
| Текст на кнопке | `--tg-theme-button-text-color` | `#1a1a1a` |

### Паттерны из `schedule.html` и `mini-app-components.css`

- Подключение: `theme.css`, **`mini-app-components.css`**, `telegram-web-app.js`, шрифт **DM Sans** (Google Fonts) для премиальных / детальных блоков (как экран детали записи `#screenDetail`).
- Карточки слотов: `border-radius: 12px`, фон `var(--tg-theme-secondary-bg-color)`; акцент — бордер `rgba(247, 166, 0, 0.45)` где уместно.
- Фильтры: чипы `border-radius: 20px`, активное состояние через `--tg-theme-button-color` / `--tg-theme-button-text-color`.
- Hero и акценты: градиент `linear-gradient(155deg, rgba(247, 166, 0, 0.14) …)`, обводка `rgba(247, 166, 0, 0.28)`, тень, радиальный блик `rgba(247, 166, 0, 0.22)`.
- CTA: оранжевый `#F7A600`, градиент кнопки `#ffc23d` → `#f0a000`, вторичный крем `#FFF3CC`, опасные действия — красные полупрозрачные стили (как в `.bd-btn--outline-danger`).
- Статусы: зелёный `#34c759`, оранжевый для «занято», приглушённый для отмены — в духе `.slot-status.*`.
- Микродвижение: например `animation` с `cubic-bezier(0.22, 1, 0.36, 1)`, лёгкий `:active` на кнопках.

### Обязательная фраза для промта

Вставляйте в конец каждого запроса к ассистенту:

> **Сделай дизайнерский шедевр, опираясь на визуальный шаблон `static/webapp/schedule.html`, токены `static/webapp/theme.css` и общие классы `static/webapp/mini-app-components.css` (кремовый/янтарный светлый режим; тёмный — чёрный фон и карточки `#1C1C1E`; акцент янтарь `#f5a623` / `#F7A600`; карточки ~12px; чипы ~20px; hero с янтарным градиентом и мягкой тенью; DM Sans для иерархии заголовков/детальных экранов). Никаких цветов вне этой системы и эталона — только переменные и те же семантические приёмы, что в `schedule.html` / `mini-app-components.css`. Не дублируй в странице CSS, который уже есть в `mini-app-components.css`. Сохрани поведение и разметку; меняй визуал и UX-полировку.**

## Универсальный промт

Подставьте имя файла вместо `<ИМЯ>.html`.

```text
Переделай мини-приложение static/webapp/<ИМЯ>.html под единый стиль с static/webapp/schedule.html: те же CSS-переменные из theme.css и общие компоненты из mini-app-components.css (подключи оба файла, не копируй их содержимое в inline-стиль). Те же принципы карточек, чипов, кнопок и hero-блоков с янтарным градиентом. Сделай дизайнерский шедевр, опираясь на визуальный шаблон schedule.html и токены theme.css (кремовый/янтарный светлый режим, тёмный с чёрным фоном и карточками #1C1C1E, акцент янтарь, DM Sans где уместно для иерархии). Не используй никаких других цветов: только var(--tg-theme-*), var(--app-*) и повторяемые из schedule.html / mini-app-components.css паттерны (янтарь/семантика). Не ломай логику и API-вызовы; только стили, типографика, отступы, состояния hover/active, пустые и ошибочные экраны.
```

## Короткая шпаргалка (добавить в конец любого промта)

- Источник правды по цветам: только `theme.css` + те же hex/rgba-приёмы, что уже есть в **`schedule.html`** / **`mini-app-components.css`** (никаких новых палитр и «украшательств» чужими оттенками).
- Образец композиции: `schedule.html`; переиспользуемые классы: `mini-app-components.css` (в т.ч. `.bd-hero`, `.bd-btn`, `.slot-card`, `.filter-btn`).
- Стек: статический HTML/CSS/JS без нового сборщика.
- **Сделай дизайнерский шедевр, опираясь на** этот шаблон и токены — без смены бизнес-логики и **без посторонних цветов**.
