# ice-inbox: скрин расписания → разбор → «да» админа

Админ загружает скрин в Mini App (Источники → «Загрузить скрин расписания»). Скрин лежит в очереди
со статусом `pending`. Ваша работа: прочитать картинку, составить спецификацию сеансов и сохранить её
как `parsed`. Публикует **только админ** кнопкой на телефоне. Сами ничего на прод не публикуйте.

## Шаги

1. Список ждущих и скачивание картинок. Запускать из каталога, где работает `railway status`:

   ```bash
   bash scripts/run_ice_ingest_prod_local.sh scripts/ice_inbox.py list --i-know-this-is-prod
   ```

   Каждая строка JSON: `inbox_id`, `arena_id`, `arena`, `city`, `image` (путь к файлу), `timezone`,
   `source_url`, `known_prices` (цены из карточки катка). Откройте каждый `image` инструментом Read.

2. Составьте спецификацию в том же формате, что `data/manual-schedules/*.json`:

   ```json
   {
     "arena_id": 20,
     "source": "пост катка, скрин от 2026-11-02",
     "defaults": {"kind": "public_skate", "duration_minutes": 45, "price_adult": "6.50", "price_child": "5.50"},
     "sessions": [{"date": "2026-11-07", "start": "14:00", "label": "Ледовый дворец"}],
     "notes": ["В посте нет дат, поставил ближайшие выходные: проверьте."]
   }
   ```

   - `arena_id` берите из `list`, не из головы.
   - Сеанс 45 минут, если на скрине нет длительности.
   - Цены только те, что видны на скрине или есть в `known_prices` / карточке. Неизвестное оставляйте
     пустым, не выдумывайте.
   - Две площадки одного катка различайте полем `label`.
   - Если на скрине только дни недели, ставьте ближайшие будущие даты и **обязательно** пишите это в `notes`.
   - В `notes` пишите каждое допущение и всё, что плохо видно (размытое время, обрезанный край). Админ
     увидит эти строки жёлтым блоком над кнопкой «Опубликовать».
   - Отменённые или нерелевантные сеансы (хоккей, тренировки, заточка) не включайте.

3. Сохраните спецификацию во временный файл и отправьте:

   ```bash
   bash scripts/run_ice_ingest_prod_local.sh scripts/ice_inbox.py submit <inbox_id> /tmp/spec-<inbox_id>.json --i-know-this-is-prod
   ```

   Команда сама проверит спецификацию тем же нормализатором, что и публикация. Если она отвечает
   «Не принято», исправьте и отправьте снова.

4. Скажите админу, что разобрано: сколько сеансов, какие допущения, и что нужно открыть «Входящие»
   (`/ice_inbox` в админ-боте) и нажать «Опубликовать».

## Чего не делать

- Не публиковать расписание самим (`load_manual_schedule.py --apply`) для скринов из очереди: решение
  за админом.
- Не править карточку катка и цены по скрину без отдельной просьбы.
