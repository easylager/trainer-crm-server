# Task

## Objective

Свести первое сообщение бота с обещанием лендинга и показать тренеру конкретную дату окончания пробного периода. Сейчас человек после CTA «Начать в Telegram» получает манифест на 10 строк, а сообщение с датой триала ему структурно не отправляется никогда.

## Business Context

Лендинг продаёт инструмент и «14 дней бесплатно» — конкретика. Бот встречает разговором о совместном строительстве платформы. Плюс обратный отсчёт по триалу — сильнейший рычаг активации — не показан ни разу, хотя подписка реально создана и тикает.

## Scope

### In Scope

- `TRAINER_AFTER_LINK_HERO` — длина, рамка, порядок «что дальше»
- Ветвление в `cmd_start` после привязки по `link_`-токену: показ триала не только для `ACTIVE`
- Согласование срока триала с обещанием лендинга («14 дней бесплатно»)

### Out of Scope

- Платный welcome-grant — TASK-012 (тот же участок кода, но отдельный дефект)
- Копирайт лендинга

## Comprehension Tips

### Facts

- Лендинг: `static/landing/index.html:55-57` — h1 «CRM для тренера на льду», лид «Telegram вместо отдельного CRM… 14 дней бесплатно», CTA «Начать в Telegram».
- Первое сообщение бота: `src/bot/messages.py:2268-2279` `TRAINER_AFTER_LINK_HERO` — «🤝 Платформа, которую строим вместе с тренерами…», три буллета, «Ты здесь не просто пользователь — твой опыт напрямую влияет на то, как платформа работает для всей индустрии», и только в последней строке — «Начни с «Обзор» … и сразу пробный период на полном тарифе» (без даты).
- Для нового тренера с лендинга состояние `BLOCKED_PROFILE` (профиль пуст), и `trainer_first_link_onboarding_html` (`src/bot/trainer_gate_text.py:17-27`) возвращает **только** hero: `_after_link_step_html` для `BLOCKED_PROFILE` отдаёт пустую строку.
- `src/bot/messages.py:2312-2318` — `TRAINER_WELCOME_TRIAL_ACTIVATED` («🎁 Пробный период — {tier_name}, до {expires_date}») отправляется в `cmd_start` только внутри `if state == TrainerAccessState.ACTIVE`. Новый тренер туда не попадает никогда.
- Триал при этом создаётся: `ensure_trainer_welcome_trial` → `create_trial_subscription` (`src/application/subscription_use_cases.py:145-190`), срок берётся из `subscription_plans.period_days` через `resolve_trial_period_days` — то есть настраивается в БД, соответствие «14 дням» с лендинга нужно проверить фактически.

### Implications

- Минимальный фикс: вынести показ триала (`tier_name` + `expires_date`) из ветки `ACTIVE` — он релевантен любому только что привязавшемуся тренеру.
- Hero стоит сократить до одного обещания + одного действия; манифест про сообщество, если он нужен, уместнее позже, а не перед первым кликом.
- Проверить фактический `period_days` у trial-плана в проде: если там не 14, лендинг врёт.
