# Task

## Objective

Сделать карту способом выбрать каток, а не украшением: кластеризация, загрузка точек по видимой области, геолокация с сортировкой по расстоянию, карточка выбранной арены. Вынести это в один переиспользуемый компонент выбора арены — для таба «Лёд», профиля тренера и онбординга.

## Business Context

Карта на Leaflet+OSM уже написана и работает (`static/webapp/catalog-main.js:4497–4720`), но живёт внутри шага фильтра: без поиска, без кластеризации и с загрузкой всех точек города. На 60 аренах Москвы `fitBounds` схлопывает пины в кашу. Параллельно тот же выбор арены в профиле тренера — плоский список чекбоксов без адресов, а в онбординге — поиск по всем городам платформы (T-6/T-7/T-8). Один компонент закрывает все три места.

## Design Reference

Экран прототипа **«Лёд — карта»**: кластер с числом, пины уровня A/B с подписью ближайшего сеанса («Чижовка · 11:00»), бледные пины уровня C, кнопка «◎ Рядом со мной», нижняя карточка ближайшей арены поверх карты, тот же ряд чипов намерения и переключатель «Список / Карта», что и в списке.

## Scope

### In Scope
- Кластеризация пинов и загрузка точек по bbox (эндпоинт из TASK-051), а не всем городом.
- Геолокация по кнопке (не при старте) + сортировка по расстоянию.
- Подпись ближайшего сеанса на пине для уровня A; приглушённые пины уровня C.
- Нижняя карточка выбранной/ближайшей арены с переходом на карточку арены.
- Выделение переиспользуемого компонента «выбор арены» (карта + поиск + список + чипы выбранного) в отдельный модуль и подключение его в: таб «Лёд», профиль тренера (вместо плоского списка чекбоксов и второго списка радиокнопок «основная площадка»), онбординг (арены выбранного города, с возможностью искать по всем городам).
- В профиле: «основная площадка» выбирается прямо на чипе выбранной арены, второй список исчезает.

### Out of Scope
- Смена картографического провайдера, свои тайлы, офлайн-карты.
- Изменения контракта API (он приходит готовым из TASK-051).
- Логика видимости арен (`is_public`) — TASK-057.

## Acceptance Criteria

### AC-001
На карте города с 60 аренами пины не перекрываются: близкие точки собраны в кластеры с числом, разворачивающиеся при зуме.
Requirement: CONFIRMED
Verification method: manual/exploratory на реальных данных Москвы + design-review

### AC-002
Точки грузятся по видимой области; перемещение карты не тянет весь город заново.
Requirement: CONFIRMED
Verification method: manual (сетевые запросы при панорамировании) + automated/integration (bbox-эндпоинт вызывается с реальными границами)

### AC-003
«Рядом со мной» запрашивает геолокацию по нажатию (не при старте), сортирует список по расстоянию и показывает ближайшую арену карточкой.
Requirement: CONFIRMED
Verification method: manual/exploratory

### AC-004
Выбрать арену в Москве занимает не более трёх действий и не требует прокрутки списка из 60 строк ни в табе «Лёд», ни в профиле тренера, ни в онбординге.
Requirement: CONFIRMED
Verification method: manual/exploratory (сценарий на всех трёх экранах)

### AC-005
В профиле тренера исчезает второй список радиокнопок «основная площадка»: выбранные арены показываются чипами, основная отмечается на чипе.
Requirement: CONFIRMED
Verification method: manual/exploratory + automated/unit (рендер компонента)

### AC-006
Арена без координат не пропадает из списка (только с карты) и это видно пользователю, а не выглядит как пропажа.
Requirement: CONFIRMED
Verification method: automated/unit + manual

## Edge Cases

### EDGE-001
Геолокация отклонена или неточна (Telegram WebView) — карта остаётся полезной, кнопка не блокирует экран.
Severity: MEDIUM
Status: OPEN

### EDGE-002
Пользователь физически в городе, где у нас нет арен — «рядом со мной» должно честно сказать это, а не показывать пустую карту.
Severity: MEDIUM
Status: OPEN

### EDGE-003
Онбординг у приграничного тренера: нужен доступ к аренам другого города при выбранном городе по умолчанию.
Severity: LOW
Status: OPEN

## Technical Notes
- Существующий код карты: `static/webapp/catalog-main.js:4497–4720`, разметка `catalog.html:159` (`#screenArena`, `#arenaMap`, легенда, поиск).
- Профиль тренера: `static/webapp/trainer-profile-main.js` (`renderArenas`, `loadArenasForCity`, `updatePrimaryArenaUi`).
- Онбординг: `static/webapp/trainer-onboarding-main.js` (`filteredArenas` — сегодня грузит все арены платформы).
- Кластеризация — библиотекой Leaflet-экосистемы, уже используемой в проекте, либо простой сеточной агрегацией на клиенте; не тянуть новую тяжёлую зависимость в Mini App без замера веса бандла.

## Tests
- integration: bbox-загрузка при панорамировании (AC-002)
- unit: арена без координат остаётся в списке (AC-006)

- design-review: карта Москвы с кластерами в обеих темах (AC-001)

## Risks
- Компонент используется в трёх местах с разными правами (клиент — только чтение; тренер — выбор). Разделить конфигурацию, а не форкать код, иначе через месяц это будут три разные карты.
