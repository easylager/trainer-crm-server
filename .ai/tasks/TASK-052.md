# Task

## Objective

Построить центральный экран эпика — карточку арены с лентой льда, где на одной временной оси живут строки двух природ: открытый лёд (read-only) и занятия (записываемые). Реализация должна максимально повторять прототип.

## Business Context

Это место, где два продукта становятся одним. Клиент, пришедший «покататься в субботу», проходит мимо блока «Тренеры на этой арене» в контексте, а не как мимо рекламы — это и есть бесплатная воронка к платящей части продукта.

## Design Reference

Экраны прототипа [`design/arenas-client-app-prototype.html`](../design/arenas-client-app-prototype.html): **«Арена (есть расписание)»** и **«Арена (расписания нет)»**. Обязательные к воспроизведению детали:
- порядок блоков: hero-фото → удобства → лента льда → тренеры → группы → практика → свежесть → «Это ваш каток?»;
- **цветовой код природы строки**: холодная (синяя) левая полоса — открытый лёд, кнопка-призрак «Билет на месте»; акцентная (янтарная) — занятие, кнопка «Записаться»/«Заявка». Легенда под лентой обязательна;
- вкладки `Сегодня` / `Завтра` / `Неделя`; день без данных в «Неделе» показывает «Данных нет», а не пустоту;
- тренер без онлайн-записи — кнопка «Написать», а не мёртвая «Записаться»;
- строка свежести и «Сообщить об ошибке» — под лентой;
- состояние уровня B: блок «Расписание уточняется» с телефоном и сайтом катка вместо пустого места.

## Scope

### In Scope
- Новая страница клиентского Mini App (например `static/webapp/arena.html` + свой JS/CSS), в существующей клиентской оболочке (шапка «Главная/Назад», нижние табы, тема).
- Все блоки карточки по порядку из прототипа, включая пустые состояния уровней B и C.
- Кнопка «Записаться» ведёт в существующий контур записи с преднастроенной ареной; «Заявка» — в существующий контур заявки в группу.
- «Сообщить об ошибке» — типизированное сообщение (поле + предлагаемое значение), а не письмо в поддержку; до готовности TASK-060 складывается в простое хранилище/уведомление админу.
- «Это ваш каток? Забрать страницу» — создаёт заявку администратору (панель оператора вне эпика).
- Deep link на карточку арены (`startapp`) — чтобы на неё можно было сослаться из бота и из будущих публичных страниц.

### Out of Scope
- Таб «Лёд» и список арен — TASK-053; карта — TASK-054.
- Покупка билета на сеанс, вместимость, онлайн-оплата — эпик это исключает.
- Отзывы об арене, пользовательские фото.

## Acceptance Criteria

### AC-001
Карточка арены уровня A показывает ленту льда за сегодня с сеансами и занятиями на одной оси, визуально различая их природу так же, как в прототипе (полоса + тип кнопки + легенда).
Requirement: CONFIRMED
Verification method: manual/exploratory со сравнением с прототипом + design-review (скриншот против эталона)

### AC-002
Вкладки «Сегодня / Завтра / Неделя» переключают ленту без перезагрузки; день без данных в «Неделе» показывает «Данных нет».
Requirement: CONFIRMED
Verification method: manual/exploratory + automated/unit (рендер недели с пустым днём)

### AC-003
Кнопка «Записаться» на строке занятия приводит к записи именно на эту арену (совместно с TASK-056), а не на основную площадку тренера.
Requirement: CONFIRMED
Verification method: automated/integration (сквозной сценарий: карточка арены → запись → бронь с этой ареной)

### AC-004
Блок «Тренеры на этой арене» показывает «Записаться» только тем, у кого доступна онлайн-запись; остальным — «Написать». Тренеров, у которых арена непубличная (TASK-057), в блоке нет.
Requirement: CONFIRMED
Verification method: automated/integration + manual/exploratory

### AC-005
Арена без расписания (уровень B) показывает блок «Расписание уточняется» с телефоном и сайтом; арена уровня C не показывает обещаний, которых не может выполнить; ни один блок не выглядит сломанным.
Requirement: CONFIRMED
Verification method: manual/exploratory на реальных данных всех трёх уровней

### AC-006
Строка свежести отражает реальные данные («обновлено N дней назад · источник»); при отсутствии источника дата не выдумывается.
Requirement: CONFIRMED
Verification method: automated/unit + manual

### AC-007
Экран работает в светлой и тёмной теме Telegram и на узком экране (360 px) без горизонтальной прокрутки.
Requirement: CONFIRMED
Verification method: design-review (обе темы, 360 px)

## Edge Cases

### EDGE-001
У арены нет ни одного фото — hero заменяется плейсхолдером, а не пустым блоком (см. TASK-049 AC-005).
Severity: LOW
Status: OPEN

### EDGE-002
Сеанс идёт прямо сейчас — должен читаться как «идёт», а не теряться между «прошло» и «сегодня».
Severity: MEDIUM
Status: OPEN

### EDGE-003
Арена закрыта на сезон, но в ленте остались материализованные сеансы (см. TASK-050 EDGE-002) — карточка обязана показать «закрыт до …» приоритетнее ленты.
Severity: MEDIUM
Status: OPEN

## Technical Notes
- Клиентская оболочка и тема: `mini-app-client-shell.js/css`, `mini-app-client-theme.css`, `client-mini-app-theme.js`.
- Геометрия и стиль элементов — по существующей дизайн-системе (`mini-app-arena-ribbon.css`, 45° срезы, янтарный CTA), а не «новый стиль ради арены».
- Данные — только из TASK-051; никакой логики уровня A/B/C на клиенте.

## Tests
- unit: рендер ленты (пустой день, сеанс «идёт сейчас», отсутствие фото)
- integration: сквозной сценарий «карточка арены → запись → бронь на этой арене» (AC-003)
- design-review: сравнение с прототипом в обеих темах (AC-001, AC-007)

## Risks
- Соблазн «улучшить» дизайн по ходу. Прототип утверждён владельцем продукта — расхождение обсуждается до, а не после реализации.
