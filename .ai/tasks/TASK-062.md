# Task

## Objective

Сделать видимым главное, что ломается на масштабе: не «упал ли сборщик», а «когда источник последний раз дал валидный результат» и «какая доля арен по городу реально актуальна».

## Business Context

На 300–500 аренах узкое место — свежесть: никто не успевает проверять, а источники ломаются тихо. Продукт при этом продолжает уверенно показывать старое расписание, и один человек, приехавший к закрытым дверям, стоит дороже сотни просмотров. Плюс это метрика самого эпика: успех измеряется долей арен уровня A, а не количеством арен в справочнике — иначе широкое покрытие будет выглядеть как рост, не будучи им (T-16).

## Scope

### In Scope
- Алерт по `ice_parser_jobs` / прогонам: нет `ok` дольше порога (каденс×N) → уведомление администратору (через существующий admin-бот). Совместимость: если слой `sources` из TASK-059 ещё жив — тот же смысл на `last_ok_at`.
- **Процент успешных прогонов** (`ok / finished` за 7 и 30 дней) по каждому job/арене — главный админский рычаг «парсер пора обновлять» (считает TASK-072, здесь — алерт и сводка).
- Алерт по устареванию фактов: доля просроченных по `valid_until` сеансов превысила порог по городу.
- Разрез в админской аналитике: **доля арен уровня A / B / C по городам**, динамика по неделям.
- Разрез «арены с ≥1 записью за 30 дней / всего арен» по городам — метрика плотности против метрики покрытия.
- Счётчик ручных правок в неделю — если он растёт вместе с покрытием, конвейер не работает.
- Еженедельная сводка одним сообщением: что протухло, где источники молчат, куда смотреть.

### Out of Scope
- Внешняя система мониторинга/APM.
- Автоматическое отключение источников — решение принимает человек.
- Дашборд для операторов катков.

## Acceptance Criteria

### AC-001
Источник, не дающий валидного результата дольше порога, порождает алерт — даже если технически ни один прогон не падал.
Requirement: CONFIRMED
Verification method: automated/integration (источник с `last_ok_at` в прошлом и нулём ошибок → алерт)

### AC-002
В админской аналитике видна доля арен уровня A/B/C по каждому городу и её изменение за последние недели.
Requirement: CONFIRMED
Verification method: manual/exploratory + automated/integration (агрегат считается корректно на тестовых данных)

### AC-003
Виден разрез «арены с записями за 30 дней / всего арен» по городам.
Requirement: CONFIRMED
Verification method: automated/integration

### AC-004
Еженедельная сводка приходит администратору одним сообщением и содержит: молчащие источники, долю просроченных фактов, изменение доли уровня A.
Requirement: CONFIRMED
Verification method: manual (получить сводку на тестовых данных)

### AC-005
Ни одна метрика не смешивает суммы в разных валютах в один итог.
Requirement: CONFIRMED
Verification method: static analysis + automated/unit

## Edge Cases

### EDGE-001
Источник обновляется раз в месяц по своей природе (сезонный каток) — порог должен быть настраиваемым на источник, иначе алерты станут шумом и их перестанут читать.
Severity: MEDIUM
Status: OPEN

### EDGE-002
Город с одной ареной: доля уровня A прыгает между 0% и 100% — в сводке нужен абсолютный счётчик рядом с долей.
Severity: LOW
Status: OPEN
