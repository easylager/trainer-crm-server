# Task

## Objective

Для небольших белорусских городов (например Бобруйск, Лида) стоимость подписки тренера
должна быть ниже базовой (текущей минской/областной) цены — гибкое ценообразование внутри
Беларуси, отдельно от расширения на Россию.

## Business Context

Часть исходного запроса владельца продукта про мультивалютность/цены (2026-09-04), явно
выделена в отдельную задачу по его же решению — не блокирует запуск России
([[TASK-043]], [[TASK-044]]), может делаться позже. Ниже приоритет, чем RU-задачи.

**Важно:** для самого тренера это не должно выглядеть как "скидка" — тренер из небольшого
города просто видит свою (более низкую) цену подписки, без пометок "скидка"/"акция"/
сравнения с ценой Минска. Незаметное геозависимое ценообразование, а не промо. См. также
[[TASK-044]] — та же логика применяется и к наценке для Москвы/МО (тренер видит просто
свою цену, без пометки "наценка").

## Scope

### In Scope

- Признак "уровня города" внутри Беларуси (минимум: столица/областной центр vs
  небольшой город) — на чём основано снижение цены.
- Пониженные тарифы `SubscriptionTierPricing`/`SubscriptionModulePeriodPricing` (currency
  остаётся BYN) для городов с признаком "небольшой".

- Добавление городов в `cities` — не требуется, все целевые небольшие города уже есть в
  проде (см. Facts).

### Out of Scope

- Валюта/RUB-тарифы — это [[TASK-043]]/[[TASK-044]], не пересекается напрямую (эта задача
  только про BYN).
- Наценка для Москвы/МО — [[TASK-044]].

## Comprehension Tips

  Минск, Гродно, Брест, Витебск, Гомель, Могилев. Остальные 22 — небольшие/районные
  города, кандидаты на пониженный тариф: Бобруйск, Лида, Барановичи, Пинск, Молодечно,
  Солигорск, Жодино, Кобрин, Берёза, Пружаны, Ивацевичи, Новополоцк, Орша, Горки, Жлобин,

  нужно — все целевые (включая примеры владельца продукта "Бобруйск, Лида") уже в БД.

- Текущие базовые BYN-тарифы см. [[TASK-044]] Comprehension Tips (crm 20, online 35,

без какой-либо пометки "скидка"/"акция" в интерфейсе.

## Decisions

### DEC-001
"Небольшой город" = любой активный BY-город, кроме Минска, Гродно, Бреста, Витебска,
Гомеля и Могилева (все 6 — база, без изменений); все 22 остальных BY-города в проде
автоматически попадают под пониженный тариф.
Reason: подтверждено владельцем продукта 2026-09-04 — исходный список без Витебска/Гомеля
был пропуском, а не намерением исключить именно их из базовой цены.

### DEC-002
Размер скидки для небольших городов — **15%** от базовой BYN-цены, по всем тарифам
(crm/online/analytics) и модулям (online/analytics/groups × 1/3/12 мес) равномерно.
Reason: точная цифра оставлена на усмотрение Claude владельцем продукта 2026-09-04
("можно 15 процентов например пока поставить") — стартовое значение, не финальное
маркетинговое решение, можно скорректировать после запуска.

## Technical Plan (как реализовано)

1. Переиспользован механизм `price_group` из [[TASK-043]]/[[TASK-044]] один в один —
   отдельное поле `cities.price_group` уже существовало, добавлять новое (`cities.tier`
   и т.п., как предполагалось изначально) не понадобилось.
2. Миграция `migrations/versions/0191_by_small_city_discount.py`: `UPDATE cities SET
   price_group = 'BY_SMALL' WHERE country = 'BY' AND name NOT IN (6 столичных городов)` —
   по имени, не по id (то же соображение, что в TASK-043). Новые города заводить не
   понадобилось — все 22 уже были в БД.
3. Та же миграция сеет BY_SMALL-строки (−15% от BY_BASE) во все три тарифные таблицы.
4. Изменений кода не понадобилось вообще — `get_tier_period_pricing`/
   `get_module_period_pricing`/`get_subscription_constructor_catalog` уже были
   параметризованы по `price_group` в TASK-044; резолв через `resolve_trainer_price_group`
   одинаково работает для `BY_SMALL`, `RU_BASE`, `RU_MOSCOW` — TASK-045 оказалась чисто
   миграцией данных, без единой строки Python-кода.
5. UI-текст не менялся (см. TASK-044 п.5) — значит пометок "скидка"/"акция" нет и не
   могло появиться.
