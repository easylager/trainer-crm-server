# V1 ingestion: parameterized parsers (Minsk)

Дата: 2026-09-05. Статус: **APPROVED владельцем продукта** (этот чат).  
Дополняет [`DESIGN-INGESTION-SYSTEM.md`](./DESIGN-INGESTION-SYSTEM.md): для Минска **не** «LLM на 150 сайтов», а **стратегия на каток**. Выход любого адаптера — **один канон** `ice_sessions` после transform+validate (§3.1).

## 0. Продуктовая граница (жёсткая)

В клиентский таб «Лёд» / карточку «покататься» попадают **только**:

- **Массовое катание** (`kind = public_skate`)
- **Свободное катание** (`kind = open_ice`) — синоним МК, если каток так называет сеанс

Не показываем и не храним как «лёд для клиента»: ОХМ, школьные группы, аренда льда под хоккей, события, дискотека-как-отдельный-продукт (дискотека на МК — это тот же `public_skate` с пометкой в `session_label`).

Цены слота — три числа, не одна строка:

- взрослая
- детская
- прокат коньков (может быть общим на арену, если каток не отдаёт её в слоте)

Горизонт: **даже один день вперёд — ок**. Минск-Арена публикует [saleframe `/service/55`](https://saleframe.minskarena.by/service/55) на ближайший день (проверено 2026-09-05: 6 сен, 17:00 и 19:00, взр. 8.50 / дет. 6.00). Каденс = **раз в сутки**.

## 1. Четыре сущности (не смешивать)

| Сущность | Имя в БД | Зачем |
|---|---|---|
| Каталожный профиль | `arena_profiles` (1:1 к `arenas`) | Карточка: адрес, район, телефон, сайт, часы, amenities, slug. Редко меняется. TASK-048. |
| Задание парсера | **`ice_parser_jobs`** | «Как и когда собирать эту арену». Метаданные реверса + расписание запусков. |
| Прогон | **`ice_scrape_runs`** | Стейтфул-попытка: статус, сколько слотов, ошибка, снимок. TTL. |
| Актуальные слоты | `ice_sessions` | Только текущие МК/свободное. После успешного прогона — replace в горизонте источника. |

Сборщик **не** пишет в `arena_profiles`. Профиль и расписание — разные потоки (как §1 старого дизайна).

### Почему не одно поле на `arenas`

`arenas` уже живёт в контуре тренеров (запись, группы). Парсерный конфиг и TTL прогонов туда не кладём — иначе карточка катка и крон начнут блокировать друг друга.

## 2. `ice_parser_jobs` — что инкапсулирует

Одна строка = одна арена × один парсер (обычно 1:1).

- `arena_id`
- `parser_key` — код стратегии (`zamok_html_v1`, `minskarena_saleframe_v1`, …)
- `is_enabled`
- `cadence` — `hourly | daily | weekly` (Минск-Арена = `daily`)
- `next_run_at`, `last_run_at`
- `config jsonb` — **всё, что нужно стратегии**: URL, API path, `service_id=55`, селекторы/regex names, BY-egress flag, timezone override, kind-filter
- `trust_level`, `notes`

Имя **job**, не «parser» в единственном числе: парсер — класс в коде; job — строка в БД, которую читает скедулер.

## 2.1 Рантайм (зафиксировано владельцем 2026-09-05)

Сбор — **не** процесс API (uvicorn/FastAPI). Чужой HTTP, таймауты и (позже) браузер не должны трогать запись к тренеру.

| Делаем | Не делаем |
|---|---|
| Тот же репозиторий и Docker-образ | Celery + Redis, RQ, Kafka, Airflow |
| Цикл `IceIngestScheduler` в **`notification_service`** (как дайджесты/nudges) | APScheduler / `FastAPI.lifespan` / `BackgroundTasks` на каждый тик |
| Будильник = `ice_parser_jobs.next_run_at` | Скрейп внутри админского HTTP |
| Админ «сейчас» → `next_run_at = now()` | Отдельный k8s Job на каждую арену |

Объём V1: ~8 минских катков × раз в сутки. Это будильник, не очередь.

Playwright, если saleframe без API не открывается — тот же воркер, пока хватает памяти; вынос в третий процесс — только если браузер начнёт валить notification loops. BY-VPS — только egress для 403, не новый ETL.

**Лимиты рантайма (надёжность > скорость), 2026-09-06:**

- Скрейп **только** в процессе скедулера. HTTP API / админ «запусти сейчас» меняет `next_run_at`, сайт не трогает.
- Параллелизм: очередь, не «все job сразу». Потолок V1: **≤4** HTTP-прогона одновременно, **≤1** Playwright/Chromium (один браузер на воркер). Пачка Chromium на Railway = OOM, не «быстрее».
- На один `host`: не больше **1** активного запроса; между ретраями backoff (например 2s → 8s → 30s), **не больше 3** попыток. Circuit breaker: 3 `blocked`/`error` подряд на хост → пропуск до следующего `cadence` (не молотить 403).
- Память Railway-воркера: HTTP+JSON+lxml укладывается в **512 МБ**. Playwright — закладывать **1 ГБ** и слот браузера = 1. Не поднимать второй воркер «на всякий случай» до профилирования.
- Тело ответа и фото недели класть в снимок прогона (hash). Если hash совпал с прошлым `ok` — **не** перепарсивать и не переписывать `ice_sessions` (кроме сдвига `observed_at` по политике TASK-072).

## 3. Скедулер и стратегия

```
ice_parser_jobs (due next_run_at)
        │
        ▼
  IceIngestScheduler          ← цикл в notification_service, не uvicorn
        │  передаёт job.config + arena_id
        ▼
  IceParser (ABC)             ← только EXTRACT, формат сайта
     ├── ZamokHtmlParser
     ├── LedByHtmlParser
     ├── ChizhovkaHtmlParser
     ├── DiamondHtmlParser
     ├── JunostWeekendParser
     └── MinskArenaSaleframeParser   ← /service/55
        │  Extraction (сырьё + черновые поля источника)
        ▼
  IceSessionNormalizer        ← TRANSFORM (общий)
        │  CanonicalSlotDraft[]
        ▼
  IceSessionValidator         ← VALIDATE (общий, отрасль + схема)
        │  ValidatedSlot[]  или отказ всего батча
        ▼
  ice_scrape_runs  (always)
        │
        ├── status=ok + slots → IceSessionPublisher → ice_sessions
        ├── status=empty     → слоты не трогаем; арену в таб «Лёд» не поднимаем
        └── status=error|blocked → то же + алерт по % успеха
```

**Жёстко:** стратегия **не** делает `INSERT` в `ice_sessions`. Клиент и админ читают только канон. Ручной ввод TASK-050 пишет в ту же таблицу теми же полями.

LLM-экстракция из старого TASK-061 — **не V1 Минска**. Возвращается только если появится источник без стабильной структуры.

## 3.1 Канонический слот (единственный формат хранения)

Контракт = TASK-050 `ice_sessions`. Источник (виджет, HTML, PNG-транскрипт, рука админа) на чтении **неразличим**, кроме provenance (`parser_job_id`, `scrape_run_id`, `observed_at`).

Обязательные поля после валидации:

| Поле | Смысл |
|---|---|
| `arena_id` | наша арена, не имя с сайта |
| `kind` | только `public_skate` \| `open_ice` на пути парсера |
| `starts_at_utc`, `ends_at_utc` | UTC |
| `local_date`, `starts_at_local`, `ends_at_local` | TZ арены (Минск = Europe/Minsk) |
| `price_adult_minor`, `price_child_minor`, `price_rental_minor` | integer, nullable; валюта города |
| `currency_code` | из города арены, не из строки «8.50 р.» |
| `status` | `active` при публикации парсером |
| `valid_until`, `observed_at` | свежесть |
| `scrape_run_id` | без прогона слот с парсера не существует |

`session_label` / `age_note` / `external_url` — опционально. Одна строка «8.50 / 6.00 + прокат» **запрещена**.

### Transform, который обязан быть общим (не копипаста в каждом парсере)

- Цена: `"8.50 р."` / `"8,50"` / `"850 коп"` → `850` minor BYN.
- Два блока на одно время (saleframe: «взрослый 17:00 8.50» + «детский 17:00 6.00») → **один** канонический слот с двумя ценами, не две строки ленты.
- `Массовое катание` / `Свободное катание` / синонимы → `public_skate` или `open_ice`. Всё остальное **drop** до валидатора.
- Локальное время арены → UTC; дата слота — локальная дата катка, не UTC-сутки.

### Validate (общий гейт, провал = не писать слоты)

- `kind` ∈ allowlist МК.
- Длительность 30–120 мин, если известен конец; если конец неизвестен — стратегия/конфиг даёт default **явно** (`job.config.default_duration_minutes`; saleframe/55 = **45**, не угадывать 60).
- Цены ≥ 0, в разумном диапазоне города; валюта = валюта города.
- Нет пересечения двух опубликованных слотов одной арены на одно и то же `starts_at` (после merge взр/дет).
- Обязательные поля заполнены; мусорные HTML-хвосты не проходят.

Невалидный батч → прогон `error` (или `empty`, если отфильтровалось до нуля слотов МК). Частично валидный набор: либо публикуем только валидные **и** пишем в прогон `slots_dropped`, либо весь прогон `error` — выбрать в TASK-061 и не смешивать по адаптерам. Рекомендация V1: **публиковать валидные, считать `slots_dropped`**, если остался ≥1 слот → `ok`.

## 4. Прогоны, TTL, список клиента

`ice_scrape_runs.status`: `ok | empty | error | blocked`.

- **ok** — есть ≥1 будущий слот МК/свободного → арена **уровня A**, попадает в таб «Лёд».
- **empty** — парсер отработал, слотов нет (сезон, касса не выложила) → **не** добавляем в список «покататься». На карточке админа: «результата нет», `last_ok_at` не обновляем.
- **error / blocked** — то же для клиента; админу виден % успеха `(ok / (ok+empty+error+blocked))` за 7 и 30 дней.

Правило «0 слотов никогда не затирает старые будущие слоты» остаётся: empty/error ≠ «удали расписание». Просроченные слоты (`ends_at < now`) не показываем и чистим TTL.

TTL (черновик, поправить в TASK-072): слоты старше 14 дней удалить; прогоны старше 90 дней удалить, кроме последнего `ok` и последнего любого.

## 5. Что подтвердил спайк (не строить вслепую)

Пилот Минска: [реестр](./data/minsk-parser-registry.yaml). Спеки extract (SPEC, 2026-09-05): [`data/parsers/`](./parsers/README.md).

**Минск-Арена:** HTML [saleframe `/service/55`](https://saleframe.minskarena.by/service/55) — пустой Vue. Живые слоты — ABWS JSON (с не-BY IP, 200):

- `GET https://abws.minskarena.by/api/v1/frame/service/55/calendar`
- `GET …/events?expand=prices&from=&to=` на локальный день (`Europe/Minsk` unix, не UTC midnight)

Снимок 6 сен: **17:00–17:45** и **19:00–19:45** (45 мин, не 60). `prices[].price` уже **минор** (850 / 600) — не ×100. Две зоны на одном event → один слот. Прокат в виджете **нет** (заточка 1200 ≠ rental). ByCard в этот день пустой — не primary. Контракт: [`parsers/minsk-minskarena.md`](./parsers/minsk-minskarena.md).

Замок / Чижовка — HTML, спеки рядом. ledlife/junost origin 403 с не-BY IP; с Globalping BY — 200, но публичный API **обрезает тело ~10 КБ** — это не продакшен-fetch. Job.config несёт `requires_by_egress: true`. Контракт: [`parsers/minsk-arena.md`](./parsers/minsk-arena.md).

## 6. Надёжность: жёсткие ограничения (2026-09-06)

Зафиксировано после reverse BY и оценки масштаба Москва+СПб. Расхождение в TASK-061/071/072 — остановиться, не «сделать гибче».

### 6.1 Что система обещает клиенту

1. **Не врать.** Слот с `valid_until < now` или **`starts_at_utc <= now`** **не показываем** (идущий сеанс = прошедший для витрины, PDEC-005). Подпись «уточняется» лучше вчерашних 19:00.
2. **Пустой прогон не затирает будущее.** `empty` / `error` / `blocked` не делают DELETE живых слотов с `starts_at > now`. Иначе один сбой кассы = «катка нет».
3. **Просроченное с источника не публикуем.** `drop_past`: слоты с `starts_at_utc <= now` (и даты на странице < локальной даты прогона) выкидываются (Витебск апр/май, виджет Немана апрель, идущее сегодня 17:30 в 18:25). Если после фильтра 0 слотов → `empty`, не «опубликовать архив».
4. **Успех job — не HTTP 200.** Успех = канон прошёл validate **или** честный терминал (`blocked` geo, `empty` сезон). 200 с пустой вёрсткой / обрезанным телом = `error` или `blocked`, не `ok`.
5. **Метрика покрытия — доля уровня A**, не «все арены CRM зелёные». Skip (нет МК, нет сетки, дубль) — штатный исход, не дефект парсера.

### 6.2 Что можно включать в `is_enabled`

- Job **не** включают без спеки `data/parsers/<city>-<slug>.md` **и** фикстуры `expected.json` (хотя бы один канонический слот **или** явный терминал `sessions: []` + причина).
- `requires_by_egress: true` (Юность, ledlife) → `is_enabled=false`, пока воркер не ходит в интернет с **реального BY IP**. Header-spoof (`X-Forwarded-For`) запрещён. Globalping — проверка достижимости, не fetch-плоскость.
- Instagram / неофициальный Telegram scrape **не V1**. Источник можно задокументировать как skip. Включать только если каток отдаст официальный токен (Graph API) — отдельное решение владельца, не адаптер «на раз».
- OCR weekly photo / PDF — **нормальная** стратегия (Брест, Орша, Шклов, Лида), не «костыль до HTML». HTTPS с битым TLS не значит «сайта нет»: пробовать **http://**, как Шклов.

### 6.3 Города и порядок масштаба

| Слой | Что |
|---|---|
| Продукт V1 таб «Лёд» | **Только Минск.** Областные спеки — задел, не обязательство включить job в том же релизе. |
| Справочник CRM | Москва 102 + СПб 49 уже в проде как каталог. Парсеры РФ **не** стартовать, пока минский конвейер (скедулер + % + правило «не врать») не поживёт в проде. Ориентир: недели зелёных прогонов, не «спеки написаны». |
| Железо | 100 job/сутки HTTP — ничтожно для Railway. Дорогое — **N уникальных адаптеров** и поломки вёрстки. Второй город = снова reverse, не «включить флаг». |

Админный бюджет остаётся **≤30 мин / неделя / город**. Если больше — пороги алертов или слишком много `is_enabled` без калибровки, не «нужен второй сервер».

### 6.4 Алерты (TASK-062), чтобы не смотреть руками 150 сайтов

Считать за 7 и 30 дней по каждому job и в сумме:

- `% успеха` = `ok / (ok+empty+error+blocked)` — для дашборда.
- Алерт человеку: нет `ok` дольше **2× cadence** (daily job молчит 48 ч; weekly — 14 дней) **или** серия `error`/`blocked`.
- `empty` после серии `ok` — алерт «касса не выложила / сезон», не авто-выключение навсегда.
- Не алертить skip-арены (job нет или `is_enabled=false`).

Калибровочный набор (TASK-066): прогон фикстур на CI при каждом изменении адаптера. Регресс селектора ловим **до** прода, ретраи сеть не лечат.
