# Система данных арен: три потока, минимум админа, катки страницы не ведут

Дата: 2026-09-04. Статус: **APPROVED (частично)** — Q1 закрыт владельцем продукта 2026-09-04: **первый город = Минск**. Остальные пункты §9 — по умолчанию из рекомендации, пока не оспорены.
Основание: «катки не ведут свои страницы — их ведём мы; сбор в основном автоматический; дальше работа бэкенда».
Связано: [`DESIGN-ARENAS-CLIENT-APP.md`](./DESIGN-ARENAS-CLIENT-APP.md) (что видит клиент), [`EPIC3-arenas-ice-discovery.md`](./EPIC3-arenas-ice-discovery.md) (экраны + 16 задач), [`design/prototypes/2026-09-arenas-system-design.html`](./design/prototypes/2026-09-arenas-system-design.html) (схема).

## 0. Вердикт

**Да, система возможна и это правильная ставка.** Не «парсер расписаний», а **операционная система правды о катке**: постоянные факты + тухнущие расписания/цены + наши живые слоты тренеров сходятся на одном экране арены.

Две оговорки, без которых план врёт:

1. **Узкое место — найти источник, а не распарсить его.** В базе есть имя, адрес, координаты; сайтов и сообществ почти нет. Пока нет URL — парсить нечего. Перепись (TASK-064) — первый измеримый шаг, не деталь.
2. **100% покрытия не будет.** Часть катков публикует афишу-картинкой, часть — нигде. Уровни A/B/C из клиентского дизайна — штатный режим неполноты. Цель: максимум уровня A и **ноль вранья** на остальных, не «все 150 зелёные».

Цель по админу — не «ноль человек», а **≤30 минут в неделю на город**: человек трогает только то, в чём система не уверена. Если бюджет превышен — это дефект порогов/источников, а не повод нанять оператора на полный день.

Если пункты выше принимаются — ниже архитектура и что меняется в эпике. Если нет — останавливаемся до кода.

## 1. Три потока правды (не смешивать)

| Поток | Что | Меняется | Срок годности | Источник правды | Через наблюдения? |
|---|---|---|---|---|---|
| **1. Постоянные** | название, адрес, координаты, телефон, сайт, часы, amenities, район, фото | редко | месяцы | справочники + админ | да |
| **2. Расписание и цены** | массовое катание, свободный лёд, аренда льда | еженедельно | **дни** | сайт / ВК / Telegram / PDF / афиша | да |
| **3. Внутренние** | слоты тренеров, группы, записи | ежеминутно | не тухнет | наша БД | **нет** |

Потоки 1–2 проходят слой `sources → observations → resolve → canonical`. Поток 3 авторитетен сам по себе: provenance здесь только замедляет.

Встречаются **только в композиции ленты льда** на карточке арены: синяя строка сеанса (внешняя, с подписью свежести) и янтарная строка занятия (наша, «Записаться»). Это граница подсистем и граница прототипа.

## 2. Конвейер потока 2 (расписания)

```
arena_sources          снимок + hash        изменилось?
(арена ↔ URL)  ─────►  raw_ref        ─────► нет → СТОП
                             │ да
                             ▼
                    LLM → строгая JSON-схема
                             │
                             ▼
              нормализация (TZ, валюта города)
                             │
                             ▼
              валидация отрасли (длительность, цена, пересечения)
                             │
                             ▼
              сверка с прошлой неделей / эталоном
                             │
                             ▼
                    ┌── ГЕЙТ УВЕРЕННОСТИ ──┐
                    │ уверенно → publish  │
                    │ сомнительно → очередь│
                    └─────────────────────┘
```

Зачем каждый шаг:

- **Снимок + hash** — отладка и переразбор; LLM только при реальном изменении.
- **LLM, не CSS-селекторы** — 150 разнородных вёрсток селекторами не живут; селекторы точечно на стабильных крупных источниках.
- **Валидация отрасли** — дешёвый фильтр галлюцинаций до человека.
- **Сверка с прошлой неделей** — расписание ритмичное; слом структуры / скачок цены → очередь, не тихая публикация.
- **Гейт уверенности** — единственный механизм «минимум админа» (§4).

Поток 1 (постоянные) — отдельный, более редкий прогон из тех же справочников (карты, 2ГИС и т.п.), без еженедельного LLM-конвейера.

Поток 3 — существующие use-case слотов/групп; в ленту попадает через read API композиции, без ingestion.

## 3. Обнаружение источников

Новая сущность **`arena_sources`**: арена ↔ URL, `kind` (`site|vk|telegram|directory|manual`), `content_kind` (`html|post|image|pdf`), `is_primary`, `discovered_by`, `confirmed_at`.

Поиск (по убыванию надёжности; доступы — спайк, не допущение):

1. Справочники организаций (2ГИС / Яндекс.Карты) по имени + координатам → сайт, телефон, часы (закрывает и поток 1).
2. Поиск «название + город» → официальный сайт.
3. Сообщество ВК / публичный Telegram.
4. Перекрёстные ссылки сайт ↔ сообщество.

Автоподтверждение **только при двух независимых признаках** (адрес + нормализованное имя). Иначе — кандидат в очередь на один клик. Ошибочная привязка хуже отсутствия источника.

## 4. Гейт уверенности (правила автопубликации)

| Ситуация | Действие |
|---|---|
| Схема ок + отрасль ок + структура как на прошлой неделе + сдвиги в пороге | **Публикуем** |
| Источник новый / без истории | Очередь, пока N успешных сверок |
| Структура сетки изменилась | Очередь |
| Цена > порога (напр. 30%) | Очередь |
| Число сеансов упало сильнее порога | Очередь |
| **Извлечение вернуло 0 сеансов** | **Никогда не публикуем.** Старые данные остаются, помечаются стареющими, алерт |
| Два источника противоречат | Очередь с обоими вариантами |

Очередь сортируется по трафику арены; есть групповые действия («принять всё от источника»). **Минуты админа в неделю — продуктовая метрика**, не пожелание.

## 5. Фото — где автоматика упирается в право

Расписание и телефон — факты. **Чужие фото скрейпить нельзя.**

1. **Дизайнерский плейсхолдер** на арену (детерминированный, в стиле продукта) — база для всех.
2. **Разовая рассылка катку** «мы сделали страницу, пришлите фото» — не «каток ведёт страницу», а opt-out контент + легитимность. Решение владельца.
3. **Своя съёмка** — топ по трафику.

Рекомендация V1: (1) везде + (2) после запуска города, если одобрено + (3) точечно.

---

## 6. Защита от тихой поломки

Катки страницы не ведут → никто кроме нас не заметит гниль. Поэтому:

- монитор **`last_ok_at` по источнику**, не «упал ли крон»;
- у факта есть **`valid_until`**; просроченное **не показываем** («уточняется» лучше лжи);
- **0 слотов с прогона никогда не затирает** ещё живые будущие слоты;
- **калибровочный набор** — фикстура на каждый `is_enabled` адаптер; без неё job не включают;
- ручная правка админа — максимальное доверие, не затирается, пока внешний источник сам не изменился;
- сырьё хранится всегда;
- рантайм, ретраи, BY-egress, запрет Instagram-V1, порядок Минск → РФ: [`DESIGN-INGESTION-PARSERS-V1.md`](./DESIGN-INGESTION-PARSERS-V1.md) §6.

## 7. Стоимость и что мерять до стройки конвейера

Порядок величины (подтверждается замером в TASK-061):

- 150 HTTP/день на проверку hash — ничтожно;
- извлечение ~раз в неделю на источник → сотни LLM-вызовов/неделю → **единицы $/неделя** на младшей модели;
- картинки дороже за штуку, объём меньше.

**Деньги не лимит. Лимит — доля машиночитаемых источников.** Поэтому **перепись (TASK-064) раньше тяжёлого конвейера**: форматы (сайт / пост / картинка / PDF / нигде) задают потолок покрытия и нужен ли OCR-модуль вообще.

## 10. Риски (коротко)

- Перепись покажет, что половина города — картинки → без 068 потолок A низкий; это знание дешевле, чем сюрприз после конвейера.
