## Почему переделываем

Вывод: карта сейчас **дополнение к поиску, а не экран**. Отсюда «маленькая» и «дешёвая».
Разбор по скриншоту `before-current-map.png` (Минск, тёмная тема):

1. **Карта ~25% экрана.** Сверху кикер, заголовок «Поиск», строка поиска, чипы — почти половина
   высоты. Снизу карточка, пилюля «Список», таб-бар. Человек нажал «Карта» — а видит окошко.
2. **Пины по умолчанию.** Капля 15px; цвет почти ничего не говорит; полезное (время) —
   в сноске над точкой, и та обрезана: «Ледовый дворец спо · 19:30». Выбранный пин не отличается.
3. **Светлая карта в тёмном приложении.** Белое пятно читается как чужой виджет — главная
   причина ощущения «дёшево».
4. **Десктопный хром.** Кнопки +/− (на телефоне масштабируют щипком), широкая плашка «◎ Рядом
   со мной» поверх пинов, «В Карты →», копирайт, логотип — пять элементов по углам.
5. **Карточка под картой, а не над ней.** Пилюля «Список» наезжает на карточку; соседние места
   не пролистать — тап по пину меняет одну карточку.
6. **Баг (исправлен в TASK-146, коммит `fix(ice-map)…кластеру`):** тап по кластеру зумил
   стандартным зумом Яндекса, который вписывает точки без учёта ярлыков (~140px) и плавающих
   кнопок — крайние места уезжали за край. Места в одном комплексе зумом не разводились вовсе.

## Паттерны, на которые опираемся

Airbnb, Google Maps, Яндекс Карты, Booking, Wolt, 2ГИС — один и тот же набор:

| Паттерн | Что даёт |
|---|---|
| Карта full-bleed, поиск и чипы **плавают** поверх | Экран принадлежит карте |
| **Нижняя шторка** с 3 положениями: сводка → карусель → список | Список и карта — одно полотно, переключатель не нужен |
| **Информация в пине** (у Airbnb — цена, у нас — время сеанса) | Пин отвечает на вопрос без тапа |
| Выбранный пин **инвертируется и растёт** | Связь «пин ↔ карточка» видна сразу |
| **Карусель синхронна с пинами** | Листаешь карточки — камера ведёт; тап по пину — карусель доезжает |
| **Тёмная подложка** в тёмной теме | Карта — часть интерфейса, а не вставка |
| Кластер **с содержимым** («3 · с 18:15»), тап открывает его места | Кластер — ответ, а не загадка |
| Геолокация — **круглая FAB** над шторкой, без +/− | Меньше хрома |

## Что рисуем (утверждено в прототипе)

### Экран
- Карта на весь экран под плавающим верхом. Верх: строка поиска с городом **внутри** (пилюля
  «Минск ▾» справа) + ряд чипов: окна времени («Сейчас / Сегодня вечером / Завтра / Выходные»),
  разделитель, тип места («Магазины» и т.д.). Подложка верха — градиент от фона к прозрачному.
- Кикер «Где и с кем заниматься» и заголовок «Поиск» в режиме карты **не показываются**.
- Чипы «Где заниматься / Тренеры» в режиме карты не нужны: на карте только места.
- Копирайт Яндекса остаётся (условия использования), прижат к левому краю над шторкой.

### Пины
- **Пин = время ближайшего сеанса в выбранном окне**: пилюля 30px «● 19:30», хвостик вниз.
  Точка-маркер в пилюле окрашена по типу места (лёд — тил, улица — светлый тил, магазин — фиолетовый).
- **Выбранный пин:** заливка брендом, тёмный текст, масштаб 1.12, к времени добавляется
  короткое имя: «18:15 · Замок».
- **Вне окна / без расписания (tier C, `outside_window`):** полая точка 14px без текста —
  место видно, но не спорит с ответом.
- Магазин: подпись «Магазин» (или часы работы — на этапе реализации решить по данным).

### Кластеры
- Пилюля: кружок с числом + «с 18:15» (минимальное время внутри). Нет сеансов в окне —
  кластер «тихий» (серая обводка, «нет сеансов»).
- Если выбранное место внутри кластера — **кластер берёт выделение** (заливка брендом).
- **Тап по кластеру:** камера вписывает все его места с полями под ярлыки и плавающий UI
  (сверху ~110px, по бокам ~80px), не глубже zoom 16; шторка показывает **только места
  кластера** («3 места рядом»). Если места в одной точке (< ~60 м, один комплекс) — камеру
  не трогаем, сразу карусель. Тап по пустой карте — назад ко всем местам.

### Шторка
| Положение | Высота | Что внутри |
|---|---|---|
| peek | ~96px | хэндл + сводка «**7 мест** сегодня вечером · 11 сеансов · ещё 2 без сеансов» |
| half (по умолчанию) | ~222px | сводка + **карусель** карточек со snap, соседняя выглядывает справа |
| full | до верха − 110px | **список**: найденные → «Поделиться подборкой» → разделитель «без сеансов» → остальные |

- Хэндл тянется пальцем, отпускание — к ближайшему положению; тап по хэндлу — следующее.
- Кнопка «Списком» / «На карте» справа в шапке шторки.
- Порядок карточек: сначала места с сеансами в окне (по времени), потом остальные.
- Карточка карусели: фото 84px, имя, адрес, строка цены, чипы времён (до 3, затем «+N»).

### Синхронизация
- Карусель остановилась на карточке → пин выбран; если пин вне видимой области (между верхом
  и шторкой) — камера плавно доводит до него, иначе камера не дёргается.
- Тап по пину → карусель доезжает до его карточки; шторка из peek поднимается в half.

### Хром
- Без +/−. «Где я» — круглая кнопка 44px справа над шторкой, едет вместе со шторкой.
  В full она скрыта.

## Решения и компромиссы

- **Тёмная подложка.** Яндекс JS API **2.1** (на ней мы сейчас) тёмной темы не имеет; она есть
  в **v3** (`theme: 'dark'`). Варианты:
  1. Остаёмся на 2.1, затемняем **только слой тайлов** CSS-фильтром
     (`invert(1) hue-rotate(180deg)` + подстройка яркости/контраста) в тёмной теме приложения.
     Пины и кластеры в другом слое — фильтр их не трогает. Дёшево, обратимо, но это хак:
     цвета воды/парков приблизительные.
  2. Переезд на v3 — честная тёмная тема и векторная карта, но это переписать `ice-map.js`
     целиком (другой API кластеризации и слоёв).
  **Выбрано для TASK-147: вариант 1.** v3 — отдельной задачей, когда будет стенд с ключом.
- **Список в full-положении.** В прототипе список живёт внутри шторки. В продукте уже есть
  полноценный список (`#iceListSec`: плашка окна, «Поделиться подборкой» под найденным,
  карточки-табло). Чтобы не держать два списка, full-положение = переход в существующий
  списочный вид (`state.view = 'list'`). Визуально — шторка «уезжает вверх» в список.
- **Подложка прототипа нарисована** SVG «по мотивам Минска»; координаты мест приблизительные,
  данные сеансов выдуманы. В продукте время в пине берётся из уже существующего
  `live.starts_at_local` списка — бэкенд не меняется.

## Урок из прототипа (перенести в продукт)

Анимация камеры через `requestAnimationFrame`: метка времени rAF бывает **раньше**
`performance.now()` в момент запуска. Без `Math.max(0, …)` прогресс первого кадра
отрицательный, кубическое сглаживание раздувает его, и масштаб на кадр улетает в ×130 —
браузер пытается растеризовать слой в сотни тысяч пикселей и виснет. Прогресс клампить в
`[0, 1]`, «мгновенный» перелёт делать синхронно.
