# Quickstart: Trainer Education Details

## Goal

Проверить end-to-end сценарий:
1) тренер добавляет образование с минимальным вводом,
2) админ модерирует через карточку полного профиля,
3) клиент видит только одобренные записи.

## Prerequisites

- Локально поднят backend и боты проекта.
- Есть тестовые роли:
  - `trainer_user` (привязанный к trainer_id),
  - `admin_user` (доступ к админ-боту),
  - `client_user` (просмотр публичного профиля).
- Применены миграции Alembic для `trainer_education*`.

## Scenario A: Create with minimum fields

1. В тренерском боте открыть профиль -> раздел "Образование".
2. Добавить запись, заполнив только:
   - тип образования,
   - учреждение,
   - программа/название.
3. Пропустить все optional поля.
4. Убедиться, что:
   - запись создана,
   - статус `pending_moderation`,
   - пользователь видит сообщение "На проверке".

## Scenario B: Admin approves

1. В админ-бот приходит карточка полного профиля тренера с изменениями, включая образование.
2. Нажать `Одобрить`.
3. Проверить:
   - запись стала `approved`,
   - создан event модерации,
   - тренеру пришло уведомление "Одобрено".

## Scenario C: Admin rejects with reason

1. Создать вторую запись образования.
2. В админ-боте нажать `Отклонить` и отправить причину.
3. Проверить:
   - статус `rejected`,
   - причина сохранена,
   - тренер получил reason и CTA на исправление.

## Scenario D: Public visibility

1. Открыть публичный профиль тренера (client path/API).
2. Проверить:
   - отображаются только `approved` записи;
   - `pending_moderation`/`rejected` не видны клиенту.

## Scenario E: Edit approved record

1. Тренер редактирует одобренную запись.
2. Проверить:
   - создаётся pending revision (или эквивалент по реализации),
   - старая approved версия остаётся видимой клиенту до новой модерации.

## Verification checklist

- Не более 3 обязательных полей при первичном вводе.
- Все пользовательские тексты на русском.
- Ошибки валидации краткие и понятные.
- Решения модерации журналируются (admin, decision, timestamp).
- Образование не отправляется в админ-бот отдельным фрагментом, только в составе полного профиля.
