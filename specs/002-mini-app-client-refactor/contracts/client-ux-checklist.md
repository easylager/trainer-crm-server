# Contract: ручной чеклист клиентского UX (бот + Mini App)

**Purpose**: Проверка [spec.md](../spec.md) и конституции § VII / § VIII перед закрытием фичи.

**Статус реализации (002)**: код и тексты приведены в соответствие с FR-002–FR-004, Mini App `client-bookings` / `client-requests` используют `var(--app-*)`. Ниже — **ручная** верификация перед мержем в прод: проставьте ✓/✗ и краткую заметку.

## Клиентский Telegram-бот

Для каждой строки: ✓ / ✗ + заметка.

| # | Проверка | § |
|---|------------|---|
| 1 | Тексты на русском, единый тон («тренер», «слот», «запись») | V, VII |
| 2 | Разметка исходящих сообщений согласована (HTML в проекте) | VII |
| 3 | Ввод пользователя не ломает разметку (экранирование при необходимости) | VII |
| 4 | Одинаковые состояния (нет слотов, ошибка, успех) — предсказуемые формулировки | VII |
| 5 | Кнопки «Назад»/отмена согласованы с продуктом | VII |
| 6 | При задержке >1–2 с — typing или короткий статус (где применимо) | VII |
| 7 | Сценарий записи: при HTTPS и Mini App текст не обещает выбор слота только в чате без кнопки Web App | spec FR-004 |
| 8 | При потере сессии — сообщение не «Сначала выберите тренера», если причина в устаревшем state | spec FR-003 |
