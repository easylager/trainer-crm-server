# Research: 005-trainer-profile-details

## Decision: Модель расширения профиля

Используем инкрементное расширение `trainer_profiles` и API-контрактов без выделения нового агрегата.

## Decision: Типы новых полей

- Справочные поля (выбор из опций) для сравнимости профилей.
- Короткие текстовые поля с лимитами для самопрезентации.

## Decision: Совместимость

Старые профили без новых полей остаются валидными; UI скрывает пустые блоки.

## Risks

- Разрастание числа полей без UX-иерархии.
- Расхождение формулировок между API и карточкой.

## Mitigation

Контракт полей + единый чеклист отображения в `contracts/trainer-profile-fields.md`.
