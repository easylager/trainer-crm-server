# Feature Specification: Shared Mini App theme (theme.css)

**Feature Branch**: `001-mini-app-theme-css`  
**Created**: 2026-03-23  
**Status**: Draft  
**Input**: User description: вынести общие CSS custom properties в `static/webapp/theme.css`, подключать во все Mini App, убрать расходящиеся цвета и стили.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Единый внешний вид экранов (Priority: P1)

Пользователь открывает разные Mini App (каталог, запись, абонементы). Схожие элементы (кнопки, карточки, фон, ошибки) выглядят одинаково по цветам и типографике.

**Why this priority**: прямое требование конституции § VIII и доверие к продукту.

**Independent Test**: визуальное сравнение двух мигрированных страниц в светлой/тёмной теме; отсутствие «случайных» hex для тех же ролей в DevTools.

**Acceptance Scenarios**:

1. **Given** добавлен `theme.css` с токенами, **When** страница подключает его первым среди стилей, **Then** фон и акцент берутся из переменных, а не из дублирующихся блоков `:root` в каждом файле.
2. **Given** две страницы используют класс первичной кнопки из общего набора, **When** меняется токен акцента, **Then** обе кнопки обновляются без правки каждого HTML.

---

### User Story 2 — Постепенная миграция без большого взрыва (Priority: P2)

Команда переносит страницы по одной или небольшими пачками, остальные продолжают работать.

**Why this priority**: 15+ HTML-файлов; полный rewrite в одном PR рискован.

**Independent Test**: немигрированная страница не ломается; мигрированная проходит ручной smoke в Telegram WebView.

**Acceptance Scenarios**:

1. **Given** часть страниц без `theme.css`, **When** деплой, **Then** они отображаются как раньше.
2. **Given** страница подключила `theme.css`, **When** удалены локальные дубликаты токенов, **Then** визуально не хуже эталона (catalog/book).

---

### Edge Cases

- Telegram передаёт свои `themeParams`: токены **SHOULD** оставаться совместимыми с существующей схемой `--tg-theme-*` (fallback или мост в `theme.css`).
- Страницы с inline-скриптами, перезаписывающими CSS-переменные: миграция **SHOULD** свести это к одному месту или документировать исключение в `research.md`.
- Админские экраны: при необходимости отдельный `data-app-role="admin"` с переопределением только семантических токенов, не новый набор «случайных» цветов.

## Requirements *(mandatory)*

### Mini App (`static/webapp/`)

- Цвета, типографика и повторяющиеся UI-элементы **MUST** опираться на общие токены и паттерны из [.specify/memory/constitution.md](../../.specify/memory/constitution.md) § VIII.

### Functional Requirements

- **FR-001**: В репозитории **MUST** существовать `static/webapp/theme.css` с семантическими custom properties (минимум: фон страницы, текст, вторичный фон/карточка, акцент, текст на акценте, подсказка, ошибка, успех при необходимости).
- **FR-002**: Каждая целевая страница **MUST** подключать `theme.css` до локальных `<style>` (или вместо дублирующего блока `:root`).
- **FR-003**: Новые экраны **MUST NOT** вводить произвольные hex для ролей, уже покрытых токенами; расширение палитры — через `theme.css`.
- **FR-004**: План миграции **SHOULD** перечислять файлы `static/webapp/*.html` и порядок (пилот → остальные).

### Key Entities

- **Design token**: именованная CSS-переменная с семантическим смыслом (`--app-*` или согласованный префикс), значение может ссылаться на `var(--tg-theme-*)`.
- **Pilot pages**: 1–2 эталонных HTML (например `catalog.html`, `book.html`), на которых проверяется схема до массового переноса.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `theme.css` подключён минимум на двух пилотных страницах; дублирующиеся `:root` цвета для тех же ролей удалены с этих страниц.
- **SC-002**: В `contracts/theme-tokens.md` задокументирован полный список обязательных токенов на время миграции.
- **SC-003**: Оставшиеся страницы имеют явный backlog в `tasks.md` (или отдельный issue) без блокировки мержа пилота.
